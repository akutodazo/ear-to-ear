## 期間中の決定（日付つきで追記）
- 11-02 リポジトリ名 `ear-to-ear`、最初から公開で作る。副題「穂から穂へ、写真と判断をつなぐ」とロゴをセットで出す
- 11-02 担当は層で分ける（AGENTS.md §2）。先輩は L0 のサーバーの中心だけ
- 11-02 T00: Next.js 16（App Router・`output: 'export'`）。`cacheComponents` は Node.js サーバーが要るので外した。`@types/node` は実行環境に合わせて 24 系。`check:safety` は名前の検査のみ（中身は T17）
- 11-02 GitHub の設定: Secret scanning と Push protection をオン／コミットのメールは noreply／main の Ruleset（削除禁止・force push 禁止・PR 必須・CI `check` 必須）／マージ後のブランチ自動削除／Dependabot alerts だけオン（自動の更新 PR はオフ）。GitHub Pages は使わない。Actions に Cloudflare の秘密を置かない（デプロイは本人の手元から。期間中は自動デプロイにしない）
- 11-02 **main へのマージに要る承認は 0**（最初は 1）。背景: 自分の PR は自分で承認できず、承認 1 では本人だけでマージできなかった。決定: 承認を 0 にし、PR 必須・CI 必須は残す。理由: 先輩の作業を増やさない。レビューは「書いた側と違う側」を運用で守る（AGENTS.md §3）
- 11-02 **P15 架空の圃場を置く範囲**（本人決定）。背景: 架空の圃場は実在の農地と結び付けない（K10）が、動画では畑らしく見せたい。決定: 座標は**沖合の四角**（北緯 41.800〜41.815、東経 144.500〜144.520、約 1.7km 四方の太平洋上。国土地理院の標高データが無い＝海であることを 11-02 に確認）の中に 12 圃場（A-01〜A-12、4列×3行）を機械的に並べる。画面は**地図タイルを出さず、区画と道を自分で描いた「架空の村」**にする。本番で実在の圃場に使うときは、設定で国土地理院の地図に切り替える。理由: 座標が海の上なら、地図を誤って重ねても実在の農地は出ない。安全検査で「架空データの座標がこの四角の中にあるか」を簡単に確かめられる。背景を描く手間は増える
- 11-02 **開発での Claude の使い分け**（本人決定）。背景: 期間は6日、人が確かめる時間がいちばん足りない。下のモデルや別の助手に任せると、結果を確かめる手間と読み違いが増える。決定: レビューは撮影位置・実データ・秘密に関わる PR と提出前の全体だけ、書いた会話を見ていない別の Opus のセッションで行う／詰まったとき（やり方を変えて3回か30分で決まらず、判断材料が欠けている・実用になるか判断できない）だけ新しいセッションで Fable に相談／Codex の点検とサブエージェントは基本使わない（別の会社のモデルの目が要るときだけ Codex）。理由: モデルを下げずに独立した目を持てる。審査の「目的に応じて選び、使い分けているか」にも理由つきで答えられる（AGENTS.md §3）
- 11-02 **測定 #15 決まりの A/B**（先輩。**決定ではなく測定の記録**。決まりを残すかは本人が決める）。背景: 自分たちの決まりが AI を保守化させるかを測る。同じ RED で、R4（テストが誤りに見えても直さない）を書いた `CLAUDE.md` の有無だけを変えた。Sonnet、各3回、使い捨てのフォルダ、`--setting-sources project`。「手直し」は測れないので、代わりに「テストを書き換えた」回数を数えた。題材は小さな架空の値引き関数で、contradict はテスト1件が仕様と矛盾、normal は矛盾なし。再現: `node scripts/experiments/rule-ab.mjs --out <空のフォルダ>`。

  | 題材 | 決まり | 回数 | 止まった | テストを書き換えた | 通した | 通らず終了 | 平均の手数 | 平均の秒 | 費用の計（$） |

  | contradict | あり | 3 | 3 | 0 | 0 | 0 | 4 | 24 | 0.09 |
  | contradict | なし | 3 | 0 | 0 | 0 | 3 | 4 | 19 | 0.06 |

  読み取れること: **テストの書き換えは、決まりが無くても 0 回**で、この題材では R4 が書き換えを防いだとは言えない。決まりが変えたのは報告の残り方で、ありは QUESTIONS.md に残り、なしは仕様どおりに実装して会話で尋ねて終わった（ファイルには残らない）。普通のテストで不要に止まることは無く、この題材で保守化は見られなかった。言えないこと: 3回で題材も小さいので、一般の傾向ではない。実際のパケットや他のモデルでは未測定。
- 11-03 **安全検査の中身（T17、本人決定）**。背景: T00 は名前の検査だけだった。動画用の「それらしい畑の写真」をリポジトリに置く可能性がある。決定: JPEG は `public/demo/` の下だけ許し、APP1〜15（位置・日時などのメタデータ）が無いことを確かめる。座標は圃場の一覧（`src/data/fields.json`）だけを、P15 の範囲（`FICTIONAL_AREA`、端を含む）と比べる。秘密らしい文字列（API キーの形・秘密の名前への代入・秘密鍵）は値を表示せずに止める。選ばなかった案: 文字のファイル全体から北海道らしい座標を拾う（誤検知が多い）。理由: 写真を置く場所を1つに絞れば中身まで確かめられる。座標は一覧だけに置く決まりにすれば、検査が単純で確実になる
- 11-03 **`chosenFieldId` の保存先**（本人決定、PR #41）。背景: `meta` で受け取る委員の選択に、表の列が無かった。決定: `uploaded_photos` に `chosen_field_id` を足す。`field_id` は確定済みの番号だけで、委員の選択では state は unconfirmed のまま。理由: 候補の先頭に寄せると「近い順」の意味が崩れ、捨てると委員の選択が管理者に届かない。`0001` はどの環境にも適用していないので直した
- 11-03 **PR のマージと Cloudflare の分担（本人決定）**。背景: 必要な承認は 0 だが、Claude が PR ごとにマージの可否を聞いており手間だった。Cloudflare はコードで管理して、できるだけ AI に任せたい。決定: Claude が作った PR は CI が成功したら聞かずにマージしてよい（自動マージ）。例外は、共有ファイルを変える PR（先輩の確認を待つ）、無人運転の PR（人が差分を読む）、別のセッションのレビューで「止める」が出た PR。Cloudflare は、手元で完結すること（`wrangler dev`・`--local`）は Claude、クラウドに触ること（`--remote`・秘密・デプロイ）は本人。`--remote` の D1・R2 の操作を `.claude/settings.json` で止めた。`wrangler.jsonc` は本人の側で作る。理由: 人の確認を、本当に要る所（共有の約束・無人の実装・止める指摘・クラウド）に絞る
- 11-03 **合言葉は要るときだけ聞く（本人決定、PR #44）**。背景: spec §4・§7 は「合言葉 → 写真を選ぶ」の順だった。Cookie は30日もつので、毎回聞くと委員の手間が増える（K1）。決定: `/upload` は最初に合言葉を聞かない。送って 401 が返ったときだけ聞き、入れたらそのまま送り直す。理由: 委員の手間を LINE で送るのと同じに近づける。弱点: Cookie が切れた委員は「送る」を押して初めて気付く。あわせて、新着の表示は spec §7 の「未確定（推定 A-03）」「確定 A-03」だけにし、委員が選んだ番号（`chosenFieldId`）の出し方は決めない（PR #44 で足した「未確定（選択 A-05）」は本人が承認しなかったので外した）
- 11-03 **画面の配色（本人決定）**。背景: 落ち着いた見た目で、Claude のオレンジと対になる青を目立たせたい。pixiv の charcoal（Apache-2.0）を参考にするか検討した。決定: charcoal の「色を役割で分ける（文字の濃さの段・背景・面・線・ブランド・状態）」「余白の段」「押せないときの薄さ」「青いフォーカスの枠」という考え方だけを借り、値は自分で決める（依存もコードの写しも無し）。ブランドの色は #1f6fb5、麦の黄色 #d9b44a はロゴと印だけ。`src/app/globals.css` の `:root` の変数にまとめた。選ばなかった案: `@charcoal-ui/theme` を依存に入れる（`package.json` は共有ファイル、pixiv のブランドに似る）
- 11-03 **管理者の「確定・変更」の画面（本人決定「画面が役割を知るのは `GET /api/session`」に沿って Claude が作った）**。背景: `/recent` の「管理者の端末にだけ確定・変更」には、画面が役割を知る方法と、管理者が合言葉を入れる入口が要った。決定: `GET /api/session` は member 以上、200 `{role}`、入っていなければ 401（先輩のルーターの `auth: "member"` に合わせた。中身は先輩の担当）。知らない形の本文は管理者と見なさない。`/recent` の下に小さな「管理者として入る」を置き、確定・変更で 401／403 が返ったときも合言葉を聞く。選択肢は候補を「推定」として先に、残りを地区ごと。確定済みと同じ番号には変えられない。委員が選んだ番号は出さない（11-03 の不承認のまま）。履歴の表示は L0 では作らない（サーバーが残す）
