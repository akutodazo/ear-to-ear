# 画面の仕様（ear-to-ear、再設計・実装の版）

状態: **実装に合わせた版**（2026-11-05、PR #153 の画面）。基準は 11-05 の本人とのインタビューの合意「**最初の視線を畑に向ける**」。禁止事項を増やさず、見た瞬間に場所と関係が分かるかで判断する。11-04 に書いた設計（シートの 3 段・目安を上に固定・AI の仮の順）は [`superseded/2026-11-04-redesign/screen-spec.md`](superseded/2026-11-04-redesign/screen-spec.md) に残した。考え方は [`design-concept.md`](design-concept.md)、見た目の値は [`design-system.md`](design-system.md)（以下 DS）の §0。全体の仕様は `docs/spec.md` §7。

画面は 3 つ＋既存 2 つ。下の帯で 地図／見比べる／刈る順番 を切り替える。

| パス | 何 | 段 |
|---|---|---|
| `/` | **地図**。空中写真の上に区画の輪郭、選んだ畑の板 | L1 |
| `/fields/[id]` | **見比べる**。2 つの比べ方、判断を残す、写真の流れ、昨年の同じ頃、履歴、引き継ぎメモ | L1・L6 |
| `/order` | **刈る順番**。記録からの下書き → 並べ替え → 委員長の確定 → **LINE に 1 枚** | 再設計 |
| `/upload`、`/recent` | 既存の L0。変えない（入口は地図の「写真を送る」） | L0 |

全画面に共通: 下の帯（地図／見比べる／刈る順番。いまの画面は淡い緑の地）、本文 18px、押せる所 44px 以上、ライト固定。選んだ畑は 3 画面で同じ（`/#A-03`・`/fields/A-03`・`/order#A-03`）。文字だけで機能や状態を説明している所には線のアイコンと状態の印を添える（文字は消さない）。架空であることの注記を画面の端に小さく（「区画の形・番号・判断は架空のもの」など）。

## 1. `/` 地図

### 1-1. 目的
委員が開いた瞬間に「どの畑が刈れるか」が場所で分かる。文字の一覧を先に見せない。

### 1-2. 構成（スマホ）
- 上: ロゴ、地区の切り替え（北地区・中地区・南地区）、「写真を送る」
- 中: 地理院タイルの空中写真（出典「地理院タイル」を右上）。区画は**道と同じ向き（北から東へ 39°）の細長い帯**を地区ごとにまとめて置く（架空。実在の境界はなぞらない）
- 区画の上の札: **箱なしの影つき文字**。1 行目は番号（小）、2 行目は名前（太字）。目安の畑は札の上に金の「目安」。未確定の写真がある畑は番号の横に白い点。**未確認は文字にしない**（塗らないことで言う）。縮小しているときは名前を隠して番号と目安だけ
- 下: 凡例（収穫可能・収穫済・未確認・目安の畑・未確定の写真）、選んだ畑の板

### 1-3. 区画の見え方（DS §0-2）
| 状態 | 塗り | 線 |
|---|---|---|
| 収穫可能 | **黄緑**（この色は収穫可能だけ） | 白の細線 |
| 収穫済 | 濃い色を薄く | 白の破線 |
| 未確認 | 塗らない | 白の細線 |
| 目安の畑 | 状態どおり | 金の輪郭 |
| 選んでいる畑 | 状態どおり（少し濃く） | **白の太線＋濃い影**（目安なら内側に金を重ねる） |

### 1-4. 板（選んだ畑）
番号と名前、判断（印＋「7/22 に収穫可能と判断」、無ければ「判断はまだありません」）、最新の写真（「最新 7/19」）、「目安の畑と見比べる」（→ `/fields/[id]`）、閉じる。選んだ畑が板に隠れるときだけ、地図を最小限動かす。

### 1-5. 状態
- 読み込み中: 区画は出し、塗りは後から
- 判断を読めない: 「読み込めませんでした」と「もう一度読み込む」
- `#A-03` で開くとその畑を選んだ状態

## 2. `/fields/[id]` 見比べる

### 2-1. 目的
この畑が刈れるかを、**写真を並べて**判断し、根拠つきで残す。

### 2-2. 上の段: 2 つの比べ方（field-share の考え方を参考に、コードは自分で書いた）
| 比べ方 | 何と比べる | 見せ方 |
|---|---|---|
| **同じ日に撮った別の畑と** | 選んだ撮影日に撮った同じ地区の別の畑。相手の既定は目安。**日をまたいで比べない** | 上下 2 つの窓。境目を指で動かす |
| **この畑の前の日と** | 同じ畑の、選んだ日より前の日 | 2 枚を重ね、境目を指で動かす（上に「前の日」の札） |

- 撮影日は「撮影日」の札の列から選ぶ。相手は**上の写真の帯**を押して、その日に撮った畑だけから選ぶ（薄い札を並べない）
- 上の段は本文と一緒に送り、札の段が流れ去った後は 2 枚の写真だけが上に残る（sticky）
- 写真が無い: 「7/19 に撮った別の畑の写真はありません」「前の日の写真はありません」。読み込みの失敗と「写真が無い」を取り違えない。この畑に写真が 1 枚も無ければ上の段ごと出さない
- 上の帯: 地図へ戻る、同じ地区の畑の切り替え（目安に金の印）

### 2-3. 本文（上から）
1. **この畑**: 番号と名前、判断の行（印＋日付＋状態）、「判断を残す」
2. **判断を残す**（開いたとき）: 状態（収穫可能／収穫済）、理由（穂の色・黄色い穂の割合・農協の判定で中止（水分超過）・同（砕けなどの傷）・その他）、短いメモ、根拠の写真（下の写真の流れから選ぶ）。下に固定の「記録する」「やめる」。合言葉が要るときはその場で聞く
3. **この畑の写真**: 撮影日ごと（日付不明は別枠）
4. **昨年の同じ頃**: 昨年と今年を**同じ形で並べるだけ**（「2025年は小麦」「昨年 7/25 に収穫可能と判断、7/29 に収穫済」「今年 7/22 に収穫可能と判断」）。**日数の差は言わない**（「あと n 日」と読めるため）。昨年の写真は出さない
5. **判断の履歴**: 新しい順。取り消したものは薄く「取り消し」。取り消しで合言葉を聞かれたら、判断の入力を閉じていても入力を出す
6. **引き継ぎメモ**（L6）: 文ごとに根拠の印（判断・写真 7/19）。印を押すと履歴の項目か写真へ。根拠の無い文は灰色で「根拠なし」。「メモを作る（管理者）」。見た目は 4・5 と同じ段（枠で囲まない）

中身が無い段は見出しごと出さない（履歴が 0 件など）。メモは「作る」を出すため残す。

## 3. `/order` 刈る順番

### 3-1. 目的
委員会で刈る順に合意し、「この順にするよ」を LINE に届ける。**順を決めるのは人**（下書きは記録を並べるだけ。AI の下書きはまだ使わない）。

### 3-2. 構成
- 上: 地図へ、地区の切り替え
- 地図（小）: 区画に順位の丸（下書きは**破線**、確定は**実線**）
- 状態の行: 「下書き（保存していません）」「11/5 に確定した順」など
- 順番の一覧: 行ごとに 丸の番号・番号と名前・判断・最新の写真の日・小さな写真。**行を長押しでつかむと、ほかの行がよけて並べ替わる**（音楽のプレイリストのように。丸の番号も動きに合わせて変わる）。▲▼ も残す
- 順位を付けていない畑: 判断の無い畑は下書きに入れない。「順位を付ける」で人が入れる
- ボタン: 「保存」（誰でも）、「この順で確定」（**委員長だけ**。委員には最初から出さない）、「記録から並べ直す」。確定と並べ直しは **2 段で確かめる**
- 次に撮る畑: 今年の写真・判断が無い畑と「足りない記録」
- 確定した後: **LINE に 1 枚**（§3-4）

### 3-3. 下書きの作り方（`services/harvest-order`）
- 順位を付けるのは**今年「収穫可能」と人が判断した畑だけ**。並びは今年「収穫可能」と判断した日の古い順 → 目安を先 → 昨年の判断の日の古い順 → 番号。順位なしの畑は昨年の判断の日の順、収穫済は外す
- 保存した順は、今の記録に合わせて直す（判断が取り消された畑は外す）
- 保存先は**端末の中**（localStorage の `ear-to-ear:order:<年>:<地区>`）。共有の保存先は先輩への依頼 `docs/requests/2026-11-05-harvest-order-api.md`。画面に「いまの保存先はこの端末だけです」と出す

### 3-4. LINE に 1 枚
- 確定した順から、**地図 1 枚の絵**（1080×1200。上に見出し、地理院タイルの空中写真、区画の輪郭と塗り、順位の丸、番号と名前、右下に出典「地理院タイル」、左下に「区画・番号は架空」）と文（「北地区の刈る順番（11/5 確定）」「1. A-03 北の3（目安）」…「この順にするよ」）を作る
- 端末の共有（Web Share）で絵と文をまとめて渡す（LINE を選べば届く）。トークンは要らない
- 共有で絵を渡せない端末: 「絵を保存」「文を LINE で送る」（`line.me/R/share`）「文を写す」に分ける
- 撮影位置は使わない（K6）。絵に入るのは区画と番号だけ
- ボットが確定のときに自動で送る形（L8 のサーバー側）はまだ無い
