# 画面の仕様（ear-to-ear、再設計）

状態: 暫定採用（[`design-concept.md`](design-concept.md) §2 の推薦案）。書いた日: 2026-11-04。**11-04 夜の本人決定**: 見た目と操作は Codex の試作を基準にする。画面の切り替えはシートの 3 段ではなく**下の帯の 3 画面**（地図／見比べる／刈る順番）。§2 のシートの中身は「見比べる」画面に、§3 の順番の段は「刈る順番」画面に、それぞれ 1 画面として置く。地図の上には選んだ圃場の小さな板（§2-2 の一行の段と同じ中身）。デモの地図の下地は地理院タイル（P15 の書き換え）。この差し替えを反映した書き直しは実装の後。部品と値は [`design-system.md`](design-system.md)（以下 DS）を参照し、ここでは繰り返さない。試作は `prototype.html`（このフォルダ）。本番コードへの組み込みは今回の対象外。

画面は 3 つ＋既存 2 つ。

| パス | 何 | 段（案） |
|---|---|---|
| `/` | **地図**（航空写真＋輪郭）と、その上に重なる**圃場のシート**（§2）・**順番の段**（§3） | L1（地図・シート）、L6 の後（順番） |
| `/fields/[id]` | 圃場ページ。シートの全画面と同じ中身を 1 ページに（静的書き出し・共有リンク用） | L1・L6 |
| `/upload`、`/recent` | 既存の L0。変えない（入口は帯の「写真を送る」と、順番の段の「未確定 n 枚」） | L0 |

全画面に共通: 上の帯（DS §12-14）、本文 18px、押せる所 56px、`prefers-reduced-motion`、ライト固定。

## 1. `/` 地図

### 1-1. 目的と優先順位
目的: 「どの畑が、目安の畑と比べてどうか」を**見た瞬間に**つかみ、1 つの畑を選んで写真の比較（§2）か順番（§3）に進む。

優先順位（見える順）: 輪郭と位置 ＞ 人の判断の塗り ＞ 目安の札 ＞ 番号・名前の札 ＞ 順番の丸 ＞ 未確定の点 ＞ 帯の操作。

### 1-2. 構成（スマホ）
```text
┌─────────────────────────────┐ 56px
│ ear-to-ear   北地区 ▾  [写真を送る] │ 帯（DS §12-14）
├─────────────────────────────┤
│                             │
│  航空写真（本番: 国土地理院の   │
│  全国最新写真。デモ: 描いた村） │
│                     [＋]     │
│   ┌──────┐  ┌──────┐  [－]   │
│   │①A-01 │  │②A-02 │        │ 輪郭＋札。塗り＝人の判断
│   │ 済7/25│  │ 可7/21│        │
│   └──────┘  └──────┘        │
│   ┌──────┐  ┌──────┐        │
│   │[目安] │  │ A-04 │        │ 目安の札は番号の札の上
│   │③A-03 │  │ 未確認│        │
│   │ 可7/21│  └──────┘        │
│   └──────┘      ・未確定の点  │
│                             │
├─────────────────────────────┤ 44px
│ ■可 ▨済 □未確認 ⓵仮 ❶確定 [目安]│ 凡例（何も選んでいないとき）
└─────────────────────────────┘
```
- 帯の「北地区 ▾」: 地区の切り替え（一覧。56px の行）。切り替えると地図がその地区の全圃場が入る位置に動き、選択は消える。地区は地図の位置で分かるので、輪郭の札に地区名は書かない（A7）
- 地図: DS §7-2。輪郭 DS §12-1、札 §12-2、目安 §12-3、丸 §12-4、未確定の点 §3-3
- 凡例: DS §12-15。圃場を選ぶとシートに置き換わる
- 地図の右上の「＋」「－」（44px）。本番は Leaflet のズームコントロールを DS §13 T10 で上書き
- 出典表記（本番）: 地図の左下、`--map-control-bg` の上に「地理院タイル」（12px 以上、リンク）。デモは「架空の村（合成）」

### 1-3. データ
| 何 | 出どころ | 備考 |
|---|---|---|
| 圃場（番号・名前・地区・中心） | `src/data/fields.json`（既存） | — |
| 輪郭 | **新規** `src/data/parcels.json`: `{ fieldId, polygon: [[lat,lng],…] }`（Q3） | デモは P15 の範囲に機械的に置いた四角を崩した形 |
| 作付け（年・作物・目安） | **新規** `src/data/seasons.json`（デモ）: `{ season, fieldId, crop, benchmark: boolean, harvestedOn: string|null }`（Q4） | 本番の表は対象外 |
| 人の判断の最新 | `GET /api/fields/summary`（既存。`latest`、`hasUnconfirmed`） | 塗り・札「可 7/21」・未確定の点 |
| 順番 | **新規** `GET /api/districts/:district/order?season=`（`HarvestOrderDraft`、DS §12-10）。デモは `src/data/order-draft.json` | 丸 |
| 下地 | 本番: 地理院タイル「全国最新写真（シームレス）」。デモ: 描いた村（P15） | 設定で切り替え（既存の方針） |

### 1-4. 操作と遷移
| 操作 | 何が起きる |
|---|---|
| 輪郭（または札）をタップ | 選択（`#A-03`）。輪郭が強調、シートが**一行**の段で出る（凡例と置き換わる）。地図は動かない |
| 地図の何もない所をタップ | 選択を解除。シートが消え、凡例が戻る |
| 指 2 本・ホイール・＋－ | 拡大・縮小。札は DS §7-2 のとおり番号だけに縮む |
| 「北地区 ▾」 | 地区の一覧 → 切り替え |
| 「写真を送る」 | `/upload`（既存） |
| シートの「目安と比べる」 | シートが半分の段に（§2） |
| シートの「順番 ▸」 | 順番の段に切り替え（§3）。選択は保つ |

### 1-5. 状態
| 状態 | 見え方 |
|---|---|
| 通常 | 上の図 |
| 読み込み中 | 下地が来る前に `--background-2` の地に輪郭だけ出す。帯の下に 1 行「地図を読み込んでいます」。判断の塗りは summary が来てから（来るまで未確認の見え方にしない: 札を出さず輪郭だけ） |
| summary が取れない | 輪郭は出す。塗り・札なし。帯の下に「判断を読み込めませんでした。もう一度読み込む」（ボタン） |
| 地区に圃場が無い | 「この地区に圃場はありません」 |
| 目安が未指定の地区 | 目安の札が無い。シートの比較の左が「比べる相手を選ぶ」（§2-3） |
| 順番がまだ無い | 丸が出ない。順番の段に「仮の順はまだありません」 |
| 未確認の畑 | **塗らない**。札「未確認」。収穫不可と書かない |

### 1-6. スマホと広い画面
- 960px 未満: 地図が全面。シート／順番の段は下から
- 960px 以上: 地図が左、右に 400px の列（DS §9）。列の上で「写真 ｜ 順番」を切り替え。何も選んでいないときは右の列に順番の一覧（地区の全圃場）

### 1-7. 件数増
- 1 地区 12〜20 圃場を想定。既定の倍率で札が重なるなら番号だけの札に（DS §7-2）。それでも重なる密度（隣接する細長い圃場）は、重心でなく輪郭の中で最も広い所に札を置く（本番で要検証）
- 3 地区以上は帯の一覧

### 1-8. 確認項目
- [ ] 明るい畑と暗い林の両方の上で輪郭が見える（二重線）
- [ ] 札の白文字が最も明るい下地の上で 4.5:1
- [ ] 収穫済の斜線と仮の順の破線が、色を抜いても区別できる
- [ ] 未確認の畑が「不可」に見えない（塗り無し・文字「未確認」）
- [ ] 選択 → 層の切り替え → 戻る、で同じ輪郭が強調されたまま
- [ ] 指 2 本の拡大と輪郭のタップが競合しない（8px の判定）
- [ ] 360px 幅で帯の 3 つが折り返さない
- [ ] 出典表記（本番）が読める

## 2. 圃場のシート（`/` の上に重なる）と `/fields/[id]`

### 2-1. 目的と優先順位
目的: 選んだ畑を**目安の畑と並べて**見比べ、昨年の同じ週を参照し、判断を残す。

優先順位: 目安 ↔ この畑の最新写真 ＞ 撮影日 ＞ 昨年の同じ週 ＞ 判断を残す ＞ 記録（履歴・引き継ぎメモ）。

### 2-2. 段と中身
```text
一行（88px）
┌──────────────────────────────┐
│ ▔▔                        ×   │
│ A-03 北の3 [目安] [可 7/21]      │
│ [目安と比べる]   [順番 ▸]        │
└──────────────────────────────┘

半分（52vh）〜全画面: 縦にスクロール
┌──────────────────────────────┐
│ ▔▔  A-04 北の4  [未確認]    ×   │
│ 2026年・小麦                   │
│ [目安と並べる ●] [この畑だけ ○]  │ 切り替え
│ 目安 A-03 北の3 │ この畑 A-04    │ 列の見出し（sticky）
│ 7/21                           │ 段の日付（sticky）
│ ┌────────┐ ┌────────┐          │
│ │ 写真    │ │ 写真    │          │ 同じ日の 2 枚、同じ大きさ
│ └────────┘ └────────┘          │
│ 7/10                           │
│ ┌────────┐ ┌ ─ ─ ─ ┐          │
│ │ 写真    │ │この日の │          │ 片方に無ければ空の枠
│ └────────┘ └写真なし ┘          │
│ ─────────────────────────────  │
│ 昨年の同じ週  [2025年]           │ DS §12-8
│ 2025年 7/19・小麦・7/24 収穫     │
│ ┌────────┐ ┌────────┐          │
│ │ 目安    │ │ この畑  │          │
│ └────────┘ └────────┘          │
│ ─────────────────────────────  │
│ 判断を残す（DS §12-12）           │
│ [収穫可能] [収穫済]              │
│ 理由 … メモ … 根拠の写真 …       │
│ [判断を残す]                     │
│ ─────────────────────────────  │
│ 記録                            │
│ 判断の履歴 … 引き継ぎメモ …       │
│ 未確定の写真 1枚 → 新着で番号を付ける│
└──────────────────────────────┘
```
- 見出し行: 番号・名前・目安の札・判断の札（DS §3-3）。「×」で閉じる（選択も解除）
- 作付けの行（DS §12-9）。小麦でない年は判断の節を出さない
- 切り替え「目安と並べる／この畑だけ」。既定は目安と並べる（目安があるとき）
- 比較の 2 列（DS §12-6）。**段 = 撮影日**。今年の写真だけ。日付の新しい順に下へ
- 昨年の同じ週（DS §12-8）
- 判断を残す（DS §12-12）。残した直後、地図の塗りと札が変わり、「残しました。仮の順に反映されます」
- 記録: 判断の履歴（取り消しは 2 段、DS §7-5）、引き継ぎメモ（L6。引用 [n] を押すと元の記録が開く）、未確定の写真の件数と `/recent` への入口

### 2-3. 目安が無いとき
- 列の見出しの左が「比べる相手を選ぶ」のボタン。押すとシートが一行に下がり、地図で別の輪郭を押すと左の列がその畑になる（選択中の畑は右のまま）。見出しに「A-07 と比べています（目安ではありません）」
- 相手を選ばないときは「この畑だけ」の 1 列

### 2-4. 昨年の扱い（条件 5・6）
| 場面 | 見え方 |
|---|---|
| 昨年に同じ週の写真がある | 2 列で写真。年の札「2025年」。「2025年 7/19・小麦」。収穫日があれば「7/24 収穫」 |
| 同じ週に無く、別の日ならある | 「同じ週の写真はありません。近い日: 7/12」とその写真（日付を明記） |
| 昨年が別の作物 | 見出し「2025年は大豆（別の作物）」。写真は出す（場所の様子として）。判断・収穫日は小麦の判断と比べないよう「大豆の記録」と書く |
| 昨年の記録が無い | 「2025年の記録はありません」。枠は出すが空 |
| 収穫日が無い | 「収穫日は記録なし」 |
| 今年の写真が無い | 今年の列に空の枠「今年の写真はまだありません」。昨年の写真を今年の列に出さない |

### 2-5. データ
| 何 | 出どころ |
|---|---|
| 今年の写真 | `GET /api/photos?fieldId=`（既存。`takenAt` の年で今年を絞る） |
| 目安の写真 | 同じ API を目安の圃場で |
| 昨年 | 同じ API の昨年分（A4。デモは静的 JSON） |
| 作付け・目安・収穫日 | `seasons.json`（§1-3） |
| 判断・履歴 | `POST /api/fields/:id/status`、`DELETE /api/status-events/:id`、summary（既存）。履歴の一覧 API は無い（前案の Q4 のまま。デモは静的） |
| 引き継ぎメモ | `GET /api/fields/:id/handover`（L6） |

### 2-6. 状態
| 状態 | 見え方 |
|---|---|
| 読み込み中 | 2 列の枠だけ先に出し、中に「読み込んでいます」（DS §12-16） |
| 写真が多い（A5 を超える） | 段が増えるだけ。10 段を超えたら「古い日を見る」で折りたたむ |
| 写真を送った直後（未確定） | 今年の列に入らない（確定済みだけ）。記録の節に「未確定 1枚」 |
| 送信失敗（判断） | ボタンの直下に赤い文字（DS §7-6） |
| 判断の 422 | 理由のコードを文に（「理由を 1 つ以上選んでください」など。T12 の `StatusInputReason` に対応） |

### 2-7. `/fields/[id]`
- シートの全画面の中身をそのまま 1 ページに（帯＋「← 地図」は `/#A-03`）。静的書き出し（`generateStaticParams`）。共有リンクと、シートが使えない環境の保険
- 広い画面では本文 640px

### 2-8. 確認項目
- [ ] 2 列が常に同じ幅・同じ高さで、日付の違う写真が同じ段に並ばない
- [ ] 昨年の写真が今年の列に出ない。年の札がある
- [ ] 別の作物の年に「別の作物」と出る
- [ ] 記録に無い収穫日・判断が作られない（「記録なし」）
- [ ] 目安が無い地区で「比べる相手を選ぶ」が動く
- [ ] シートのつまみの 3 段の吸着。一行より下に閉じない
- [ ] 判断を残すと地図の塗りが変わり、順番の段に反映される
- [ ] 試作の合成写真に「合成」の札がある

## 3. 順番の段（`/` の上に重なる）

### 3-1. 目的と優先順位
目的: AI が記録から並べた**仮の順**を、根拠と足りない情報を見ながら**指で直し**、保存・確定する。地図の番号が追従する。

優先順位: 順位の丸と写真 ＞ 番号・名前・判断の札 ＞ 根拠の 1 行 ＞ 足りない情報 ＞ 保存・確定。

### 3-2. 構成
```text
┌──────────────────────────────┐
│ ▔▔  北地区の収穫順        ×    │
│ 記録から並べた仮の順（7/21 15:40）│
│ 保存していません                 │ 未保存のとき
│ [仮の順を保存]  [確定する]       │ 確定は委員長だけ
├──────────────────────────────┤
│ ⓵ [写真] A-03 北の3 [目安][可7/21] ≡│
│    7/21 に収穫可能の判断 [1]     │
│ ⓶ [写真] A-04 北の4 [可 7/21]    ≡│
│    目安と同じ日に判断 [2]、昨年は │
│    目安の翌日に収穫 [3]          │
│ ⓷ [写真] A-02 北の2 [未確認]     ≡│
│    昨年は目安の 2日後に収穫 [4]   │
│    足りない: 判断                 │
│ ──── 情報不足（順位を付けていません）│
│   [空枠] A-07 中の3 [未確認]      ≡│
│    足りない: 今年の写真、判断       │
├──────────────────────────────┤
│ 使った記録: 判断 6件、写真 11枚、  │
│ 昨年の収穫日 10件               │
│ 未確定の写真 2枚 → 新着で番号を付ける│
└──────────────────────────────┘
```
- 行は DS §12-10。根拠の [n] は DS §12-11（押すと元の記録がこの段の中で開く）
- 情報不足の群の行も持ち手で**順位ありの群に動かせる**（人が決める）。動かすとその行の「足りない」は残したまま丸が付く
- 「仮の順を作る」（委員長、`CLAUDE_ENABLED` のとき）: 仮の順が無いとき、または作り直すとき。作り直しは 2 段（人が並べた順が消えるため）

### 3-3. 操作と遷移
| 操作 | 何が起きる |
|---|---|
| 持ち手を上下に動かす | 並べ替え（DS §7-4）。地図の丸の番号が即時に付け替わる。「保存していません」 |
| 行の持ち手以外をタップ | その圃場を選択（地図が寄る）。段は開いたまま |
| 行の写真をタップ | シートに切り替え（写真の比較）。選択は保つ。「順番 ▸」で戻る |
| 「仮の順を保存」（委員） | `PUT …/order`（draft）。直下に「保存しました」 |
| 「確定する」（委員長） | 2 段 → `state: confirmed`。丸が実線に。ボタンが「確定し直す」に |
| 確定後に動かす | 丸は実線のまま、段の上に「確定した順と違います。確定し直すか、元に戻す」 |
| 「×」 | 段を閉じ、シート（一行）か凡例に戻る |

### 3-4. AI の仮の順（本番の作り方。今回は仕様だけ）
- Worker が記録（summary の最新の判断、判断の履歴、写真の撮影日、昨年の収穫日、目安）を集め、Claude に**並べ替えと根拠の文**だけを求める。写真の画像は送らない（記録の文字だけ）。引用は K17 と同じカスタムコンテンツ
- 並べる材料の優先: ① 人の「収穫可能」の判断の日付（早い順）② 目安の判断との日数差 ③ 昨年の収穫日の順 ④ 今年の写真の撮影日。材料が ①〜③ のどれも無い圃場は `rank: null`（情報不足）
- 書かせない: 成熟度、水分、収穫予定日、「〜そう」。`missing` は Worker が機械的に付ける（Claude に任せない）
- 1 日の上限と `CLAUDE_ENABLED` は既存の決まり

### 3-5. 状態
| 状態 | 見え方 |
|---|---|
| 仮の順が無い | 「仮の順はまだありません」＋「仮の順を作る」（委員長）／持ち手で並べる（全圃場が情報不足の群に） |
| 作っている | ボタンが「作っています…」（`aria-busy`、不透明度 1）。30 秒で打ち切り「作れませんでした。もう一度」 |
| 全圃場が情報不足 | 順位ありの群が空「順位を付けられる記録がまだありません」 |
