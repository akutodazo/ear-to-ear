# デザインシステム（ear-to-ear）

状態: 暫定採用（[`design-direction.md`](design-direction.md) §4 の案 A「台帳」）。書いた日: 2026-11-04。値はすべて CSS カスタムプロパティで `src/app/globals.css` の `:root` に置く（UI ライブラリ無し、Next.js 16 の静的書き出し、AGENTS §4）。今の `globals.css` との差分は §13。画面ごとの使い方は [`screen-spec.md`](screen-spec.md)、判断の理由は [`design-decisions.md`](design-decisions.md)。

書き方の約束:
- **基礎値**（`--palette-*`、`--font-size-*`、`--space-*`）は画面から直接使わない。**用途トークン**（`--text-1`、`--brand`、`--status-ready` など）を使う
- 「使わない場面」を書いてあるものは、迷っても使わない。例外を作るときは `design-decisions.md` に 1 行足す
- 数値の出典: 余白の刻み・型の段・遷移の長さ・状態の種類は design-review の checklist、コントラストと押せる大きさは WCAG 2.2（accessibility）。屋外・手袋のために上げた所はその旨を書く

## 1. 原則（5 つ）と、やらないこと

| # | 原則 | 何を意味するか | 出典 |
|---|---|---|---|
| P1 | **番号と日付が先、飾りは後** | どの画面でも最初に目に入るのは圃場番号（A-03）と状態、次に撮影日。線・枠・色は情報を運ぶときだけ置く | spec §7「数字は控えめに。一覧では番号・日付・写真・判断の色だけ」、frontend-design |
| P2 | **日なたでも手袋でも、読めて押せる** | 本文のコントラストは 7:1 を目標（最低 4.5:1）、UI の線と印は 3:1 以上。押せる所は 56px 以上。面は影ではなく 1px の線で分ける。ライト固定 | `globals.css` 冒頭、accessibility、beautiful-shadows の注意 |
| P3 | **状態は色だけで言わない** | 未確定・確定・収穫可能・収穫済・根拠なしは、必ず**文字＋印**。色は補助 | WCAG 1.4.1、design-review |
| P4 | **仮のものは仮に見せる** | 「推定」「未確定」「日付不明」「根拠なし」は、文字に加えて麦色の線・灰の文字・破線で、確定と見分けがつく | K2、spec §2、L6 |
| P5 | **動くのは応答のときだけ** | 押した・送れた・読み込んだに短く応える。自動で動く飾りは無い。記憶に残る瞬間は「送れた」の 1 か所 | frontend-design、oil-ui の 6、apple-design |

**やらないこと**（理由は `design-direction.md` §2-3。採用するなら `design-decisions.md` に理由を書く）:
グラデーションの地、ガラス・ぼかし、背景の光、影で浮かせる、ダークモード、ヒーロー（大きなキャッチコピー）と集計のタイル、絵文字・装飾アイコン、英字のラベル（STATUS など）、文字の逐次出現・数字のカウントアップ、ホバー前提の表現、写真の上に重ねた文字、全部同じ角丸。

## 2. トークンの置き方

```css
/* src/app/globals.css の :root。基礎値 → 用途の順。画面は用途トークンだけを使う */
:root {
  color-scheme: light;        /* ライト固定（屋外。design-decisions D3） */
  /* 2-1 基礎値 */  /* 2-2 用途トークン */  /* 2-3 部品の値 */
}
```

命名: `--text-*`（文字）、`--background-*`（ページの地）、`--surface*`（面）、`--border*`（線）、`--brand*`（押せるもの）、`--pending*`（未確定）、`--status-*`（判断）、`--assertive*`（誤り）、`--space-*`、`--radius-*`、`--font-size-*`、`--line-*`、`--duration-*`、`--control-*`。今ある名前はできるだけ残す（§13）。

## 4. 文字

### 4-1. フォント

```css
font-family: system-ui, -apple-system, "Segoe UI", "Hiragino Sans", "Noto Sans JP", "Yu Gothic UI", sans-serif;
```

既存の並びに `"Yu Gothic UI"` を足す（Windows で `Segoe UI` が日本語を持たないときの代替。Windows 10 以降は `system-ui` が Yu Gothic UI になるので、実際には保険）。Web フォントは読み込まない（電波の弱い畑、静的書き出し、1 系統で足りる）。

数字と番号: `font-variant-numeric: tabular-nums;` を `body` に。圃場番号（A-03）・日付・枚数の桁がそろう。

### 4-2. 段（型の 5 段。各段は 1.2 倍前後）

ルートは 18px（既存）。rem で書く。

| トークン | 値 | 用途 | 太さ | 行間 |
|---|---|---|---|---|
| `--font-size-h1` | `1.5rem`（27px） | ページの見出し（`h1`） | 700 | `--line-tight` 1.3 |
| `--font-size-h2` | `1.2rem`（21.6px） | 節の見出し（撮影日、「判断の履歴」）、番号の強調（`.label`） | 700 | 1.4 |
| `--font-size-body` | `1rem`（18px） | 本文、ボタン（副）、入力欄の文字 | 400 | `--line-body` 1.6 |
| `--font-size-note` | `0.95rem`（17px） | 補足（`.note`） | 400 | 1.5 |
| `--font-size-badge` | `0.9rem`（16.2px） | 印の文字 | 700 | 1.4 |

16px より小さい文字は作らない（iOS の入力欄の自動拡大、屋外の可読性）。主ボタンの文字は `1.1rem`（既存）。

### 4-3. 日本語の扱い

- 1 行の長さ: 本文の幅は最大 640px（約 33 字）。広い画面でも本文の列は 640px を超えない（§9）
- 折り返し: `body { overflow-wrap: anywhere; line-break: strict; }`。見出しと 1 文のまとめは `text-wrap: balance; word-break: auto-phrase;`（既存 `.balance`。対応しないブラウザはそのまま）
- **折らない単位**: 圃場番号「A-03」、候補「A-06（約50m）」、日付「2026年7月21日」、枚数「3枚」は `white-space: nowrap`（既存 `.nowrap` を日付にも）
- 長い語の切れ目: 「農協の判定で中止（水分超過）」は括弧の前で折れてよい。印（badge）の中では折らない（印が 2 行になるなら印の外に文字を出す）
- 約物: 文中の区切りは「・」、文の終わりは「。」。英字の略語は使わない（「ID」でなく「番号」）
- 句読点だけが次の行に残ることを避けるために `text-wrap: balance` を見出し・まとめに限る（本文に掛けると行末がそろわない）

## 5. レイアウトと余白

### 5-1. 余白の段（4・8 の刻み。既存）

| トークン | 値 | 用途 |
|---|---|---|
| `--space-4` | 4px | 行の中の文の間（`.stack-tight`） |
| `--space-8` | 8px | 印と文字、写真の格子の隙間 |
| `--space-16` | 16px | 面の中の余白、行の間、ページの左右（スマホ） |
| `--space-24` | 24px | 節の間、ページの上下 |
| `--space-40` | 40px | 大きな区切り（送った後のまとめの前後、地図と一覧の間） |

12px は作らない（迷ったら 8 か 16）。

### 5-2. 幅

| トークン | 値 | 用途 |
|---|---|---|
| `--page-narrow` | 640px | `/upload`、文章の列、合言葉の入力 |
| `--page-wide` | 1040px | `/`（地図＋一覧）、`/recent`、`/fields/[id]`。**広い画面でだけ**効く（§9） |
| `--thumb-list` | 120px（広い画面 160px） | 一覧の行の写真 |
| `--thumb-grid-min` | 100px（広い画面 160px） | 格子の写真の最小幅 |

### 5-3. 並べ方

- 縦の積み（`.stack` 16px、`.stack-tight` 4px）と横の並び（`.row` 16px、折り返す）の 2 つだけ
- 一覧は `ul > li > article` で、行は `grid-template-columns: var(--thumb-list) 1fr`（既存 `.card-row`）
- 格子は `repeat(auto-fill, minmax(var(--thumb-grid-min), 1fr))`（既存 `.photo-grid`）
- 主要な操作が 1 画面に 1 つ（design-review の「焦点 1 つ・主要操作 1 つ」）。`/upload` は「送る」、`/recent` は「更新」、圃場ページは「判断を残す」

## 6. 形状と装飾

### 6-1. 角

| トークン | 値 | 用途 |
|---|---|---|
| `--radius-4` | 4px | 印（badge）、入力欄の中の小さな要素 |
| `--radius-8` | 8px | 行・カード・入力欄・写真・面 |
| `--radius-16` | 16px | ボタンだけ |

角に段を付ける（frontend-design）。**カードは 16 → 8 に下げる**（カードは入れ物で、押せるものではない。16 の角を持つのはボタンだけになり、押せるものが形で分かる）。

### 6-2. 線と面

- 面は `--surface` に `1px solid var(--border)`。**影は使わない**（屋外で見えない。beautiful-shadows の「境界線の代わりに影に頼らない」）
- 状態の左線: `border-left: 6px solid`（未確定＝`--pending-line`、矛盾＝`--assertive`、収穫可能＝`--status-ready`、収穫済＝`--status-done`）。左線は印の文字と**必ず**一緒に
- 仮の見え方: 取り消した判断と「根拠なし」は `--text-3` の文字＋`1px dashed var(--border-strong)` の枠（P4）
- 区切り線は使わない。節は見出しと余白（24px）で分ける

### 6-3. 写真

- 一覧の写真: `aspect-ratio: 4 / 3`、`object-fit: cover`、角 8px、地は `--background-2`（読み込み中の置き場）。縦長の写真は中央で切れる（一覧は見つけるための手がかりで、全体は開いて見る）
- 格子の写真: 正方形に切らず `4 / 3` のまま（ドローンの写真は横長が多い。推定）
- 写真の上に文字・印を重ねない（P2。例外は根拠の写真を選ぶときの選択の印で、写真の**角**に 32px の白地の四角を置く。§12-6）
- 開けない写真: 面に `--text-3` で「開けない写真」

### 6-4. アイコン・ロゴ

- 画面の中にアイコンは置かない。状態は文字の印で表す。戻る道の「←」は文字として残す（既存。リンクの**先頭**で、frontend-design が避ける「末尾の →」ではない）
- ロゴ（`src/app/icon.svg`: 青の地に麦の穂）はホーム画面のアイコンとページの見出しの脇だけ。愛称・ロゴ案は 11/6 に決まるまで文字の「ear-to-ear」

## 7. 操作の表現

### 7-1. 押せる大きさ

| トークン | 値 | 根拠 |
|---|---|---|
| `--control-height` | 56px | ボタン・リンクの行・選択肢。WCAG の推奨 44px を手袋のために上げた（既存） |
| `--input-height` | 52px | 入力欄・select（既存） |
| 隣り合う押せるものの間 | 8px 以上 | 誤タップ |

### 7-2. 状態（すべてのボタン・入力に持たせる）

| 状態 | 見え方 |
|---|---|
| 通常 | §12 の各部品 |
| hover（PC だけ） | 主: `--brand-hover`。副: 地を `--brand-soft`。150ms |
| **active（押している間）** | `transform: scale(0.98)`、100ms ease-out（apple-design の即応答。手袋でも「押せた」が分かる） |
| focus-visible | `box-shadow: var(--focus-ring)`、`outline: none`（既存）。マウスのクリックでは出ない |
| disabled | `opacity: var(--disabled-opacity)`、`cursor: default`。文字は変えない |
| **busy（待っている間）** | `aria-busy="true"` のとき不透明度 1 のまま、文字を「送っています…」「確かめています…」に変え、`cursor: progress`（既存、Issue #69）。押せない |
| selected（切り替え・選んだ選択肢） | 枠と文字 `--brand`、地 `--brand-soft`、`aria-pressed` か `aria-checked`（既存 `.button-toggle-on`） |

### 7-3. 誤タップへの備え（手袋）

- 取り消しのような戻しにくい操作は **2 段**: 1 回目で同じ場所のボタンが「もう一度押すと取り消します」（枠 `--assertive`）に変わり、5 秒で元に戻る。2 回目で実行。モーダルは出さない（画面の外に指を動かさない）
- 「外す」「選ばない」のように戻せる操作は 1 段
- 送る・確定は 1 段（やり直せる: 同じ写真は 409、番号は訂正できる）

### 7-4. 結果の知らせ方

- 結果は**押した所の近く**に文字で出す（写真ごとの結果は写真のカードの中、確定の結果は確定フォームの下）。画面の端のトーストは出さない（屋外で視線が動く、消えると読み直せない）
- 送った後のまとめだけは面（§12-8 の `panel-ok`）で、画面の中へ滑り込ませる（P5 の「1 か所」）
- 文字の結果が出る場所には `aria-live="polite"`（成功）か `role="alert"`（失敗）を付ける

## 8. 動き

| トークン | 値 | 用途 |
|---|---|---|
| `--duration-fast` | 100ms | 押している間の縮み |
| `--duration-base` | 150ms | 色・枠の変化（hover、選択） |
| `--duration-enter` | 250ms | 面が現れる（送った後のまとめ、合言葉の入力）。`opacity 0 → 1` と `translateY(8px → 0)`、ease-out |

- 動かすのは `transform` と `opacity` だけ。`height` や `top` は動かさない（レイアウトのずれ、電池）
- 自動で繰り返す動きは無し。読み込み中は文字（「読み込み中…」）で足りる。3 秒を超える待ち（送る）は進み具合の文字（「送っています…（2/3枚）」。既存）
- `@media (prefers-reduced-motion: reduce)` で `--duration-*` をすべて `0ms` にし、`scrollIntoView` の `behavior` を `auto` に

## 10. アクセシビリティ

- `<html lang="ja">`（既存）。ページの `title` は「画面名 — ear-to-ear」（既存）
- コントラスト: 本文 7:1 目標・4.5:1 最低、印と線 3:1 以上（§3-1）。色だけで意味を伝えない（P3）
- すべての入力に `label`（既存の `label > input` の形）。合言葉の欄は `type="password"`、`autocomplete="current-password"`、**貼り付けを禁じない**（WCAG 3.3.8）。同じ端末に 30 日は再入力を求めない（3.3.7。11-03 決定と一致）
- 誤りは「何が起きたか＋どうするか」の文で（§11）。入力の誤りは欄の直下に `role="alert"`、最初の誤りの欄に `focus`
- 読み込み・送信の進み具合と結果は `aria-live="polite"`。失敗は `role="alert"`
- `:focus-visible` を消さない。固定の帯があるので、`scrollIntoView` や `focus` で動かす要素に `scroll-margin-bottom: 96px`
- 押せるもののラベルは文字（アイコンだけのボタンを作らない）
- 写真の `alt`: 一覧は「確定 A-03」などの状態の文（既存 `assignmentLabel`）、格子は「A-03 2026年7月21日の写真」（既存）
- 動きは `prefers-reduced-motion` に従う（§8）。自動再生・点滅は無し
- キーボードだけで送る・更新・確定・判断ができる（select と button で組む。独自のドラッグは作らない）

## 12. 部品（コンポーネント）

今回の画面に要るものだけ。既存のクラス名を残し、変える所は §13 に書く。各部品は「見た目／バリエーション／状態／使う場面／使わない場面」。

### 12-1. ボタン `.button`

- 見た目: 高さ 56px、左右 24px、枠 2px、角 16px、太字、文字 1.1rem（主）／1rem（副・小）
- バリエーション:
  - **主** `.button-primary`: 地 `--brand`、文字 `--text-on-brand`。**1 画面に 1 つ**（送る・更新・入って送る・判断を残す）
  - **副**（既定）: 地 `--surface`、枠と文字 `--brand`（新着を見る、続けて送る、確定する）
  - **小** `.button-small`: 高さは 56px のまま、左右 16px、枠 `--border-strong`、文字 `--text-2`（外す、管理者として入る、取り消す）
  - **切り替え** `.button-toggle` ＋ `.button-toggle-on`: `aria-pressed`。選ぶと枠と文字 `--brand`、地 `--brand-soft`（未確定だけ見る、収穫可能／収穫済の選択、理由の選択肢）
  - **幅いっぱい** `.button-block`（送るの帯）
  - **危険の 2 段目** `.button-danger`（新規）: 枠と文字 `--assertive`、地 `--assertive-soft`。取り消しの 2 回目にだけ
- 状態: §7-2 のすべて。`label.button > input[type=file]` の形（写真を選ぶ）は `:has(input:focus-visible)`・`:has(input:disabled)` で同じ見え方（既存）
- 使わない場面: 文中のリンクをボタンにしない。アイコンだけのボタンを作らない。主ボタンを 2 つ並べない

### 12-2. 入力 `.input`、select、textarea

- 見た目: 高さ 52px、枠 2px `--border-strong`、角 8px、文字 1.1rem、地 `--surface`。ラベルは上に、`label` 要素で包む（既存）
- バリエーション: 文字（合言葉）、select（番号を選ぶ。`optgroup` で「推定」と地区。既存）、**textarea**（新規。判断のメモ。最低 3 行、`rows=3`、下に「あと n 字」を `.note` で。200 字を超えたら `--assertive` の文字と `aria-invalid`）
- 状態: focus-visible（枠色は変えず `--focus-ring`）、disabled、誤り（枠 `--assertive`、直下に文）
- 使わない場面: 置き場の文字（placeholder）に説明を入れない（消えると読めない）。ラベルを省かない

### 12-3. 印 `.badge`

- 見た目: 高さ 28px 前後、左右 8px、角 4px、太字 0.9rem、**折らない**
- バリエーション（文字＋色。色だけにしない）:

| クラス | 文字 | 地 | 文字色 |
|---|---|---|---|
| `.badge-pending` | 未確定 | `--pending` | `--text-1` |
| `.badge-done` | 確定 | `--brand-soft` | `--brand` |
| `.badge-alert` | 確定（番号なしの矛盾） | `--assertive` | `--text-on-brand` |
| `.badge-ready`（新規） | 収穫可能 | `--status-ready` | `--text-on-brand` |
| `.badge-harvested`（新規） | 収穫済 | `--status-done` | `--text-on-brand` |
| `.badge-none`（新規） | 判断なし | なし（枠 1px `--border-strong`） | `--text-2` |
| `.badge-revoked`（新規） | 取り消し | なし（枠 1px dashed） | `--text-3` |

- 使わない場面: 押せるものとして（印は押せない）。文章の中。「農協の判定で中止」など理由を印にしない（理由は文字の列）

### 12-4. 写真の行 `.card.card-row`（一覧の 1 枚）

- 見た目: 面、枠 1px、角 8px、左に写真 `--thumb-list`、右に 印 → 番号（`.label`、1.2rem 太字）→ 撮影日（`.note`）。状態の左線 6px（`.card-pending`・`.card-alert`）
- バリエーション: 管理者の行（下に確定フォームが全幅で入る `.card-row-full`。広い画面では右の列）
- 状態: 通常／確定・変更を送っている間（フォームのボタンが busy）／結果の文（フォームの下）
- 使う場面: `/recent`
- 使わない場面: 圃場ページ（そこは格子）。行の中に 2 つ目の主ボタンを置かない

### 12-5. 写真のカード `.card`（送る前の 1 枚）

- 見た目: 面、角 8px、上に写真（幅いっぱい、4:3）、下に 撮影日／候補（一番近い候補だけ距離つき `.label.nowrap`、ほかは `.note`）／番号を選ぶ select／結果の文／「外す」
- 状態（`ItemStatus`）: reading（撮影日「読み取り中…」）／ready／sending（select と外すが消える、結果「送っています…」）／sent（結果 `.note-ok`）／duplicate（結果 `.note`「送り済み（同じ写真）」）／failed（`.note-alert`、外すが戻る、送り直せる）／unusable（写真の所に「開けない写真」、情報は出さない）
- 使う場面: `/upload` だけ
- 使わない場面: 一覧

### 12-6. 写真の格子 `.photo-grid`

- 見た目: `minmax(var(--thumb-grid-min), 1fr)`、隙間 8px、各写真 4:3、角 8px。写真を押すと元の大きさで開く（新しいタブ。既存）
- バリエーション: **選べる格子**（新規。根拠の写真を選ぶ）。各写真が `label > input[type=checkbox]` で、選ぶと枠 3px `--brand` と、右上の角に 32px の白地の四角に「✓」ではなく番号（1〜5、選んだ順）。5 枚選ぶと残りは `disabled`（薄く）。写真の上の文字はこの四角だけ（§6-3 の例外）
- 状態: 読み込み中の置き場（地 `--background-2`）／開けない
- 使う場面: `/fields/[id]` の撮影日ごと、根拠の写真を選ぶ
- 使わない場面: `/recent`（番号と状態が要るので行）

### 12-7. 日付の見出し `.day-heading`

- 見た目: `h2`、1.2rem 太字、右に `.note` で「n枚」。「日付不明」は最後に置き、見出しの色を `--text-2` に（P4）
- 使う場面: 圃場ページの格子の上
- 使わない場面: 新着（新着は送った順で、日付でまとめない）

### 12-8. 面 `.panel`

- 見た目: 角 8px、左線 4px、余白 16px
- バリエーション:
  - **情報**（既定。**変更**: 左線 `--brand`、地 `--brand-soft`）: 合言葉の入力、「位置が取れない写真は管理者が番号を付けます」のような説明
  - **できた** `.panel-ok`（**変更**: 左線 `--status-ready`、地 `--status-ready-soft`）: 送った後のまとめ、判断を残した後
  - **未確定** `.panel-pending`（新規: 左線 `--pending-line`、地 `--pending-soft`）: 「未確定の写真が 3 枚あります」のように未確定に関する知らせ
  - **誤り** `.panel-alert`（新規: 左線 `--assertive`、地 `--assertive-soft`）: ページ全体の失敗（「新着を読み込めませんでした。更新を押してください」）
- 状態: 現れるとき 250ms（§8）。消えるときはすぐ
- 使わない場面: 飾りの囲み。行の中

### 12-9. 更新の行（道具の行）

- 見た目: `.row` に 主ボタン「更新」＋ `.note`「HH:MM 時点」。2 行目に切り替えと件数（既存）
- 状態: 読み込み中はボタンが busy「読み込み中…」。時刻は前の値のまま
- 使う場面: `/recent`、`/fields/[id]`、`/`（地図）
- 使わない場面: `/upload`（更新するものが無い）

### 12-10. 下に固定の帯 `.action-bar`

- 見た目: `position: sticky; bottom: 0`、上に 24% のグラデーションで地に溶ける（既存。これは面の塗りでなく背景への溶け込みで、§1 の「グラデーションの地」には当たらない）。中は主ボタン 1 つ（幅いっぱい）
- 状態: 送れる写真が 0 なら帯ごと出さない（既存）。busy
- 使う場面: `/upload` の送る、圃場ページの「判断を残す」（入力中だけ）
- 使わない場面: 2 つ以上のボタンを入れない

### 12-11. 戻る道 `.back-link` とページの見出し

- 見た目: 「← トップへ」、高さ 56px のリンク（既存）。`h1` は 1.5rem。圃場ページの `h1` は「A-03」＋ `.note` で「北の3（北地区）」（既存）
- 使う場面: トップ以外のすべてのページの先頭
- 使わない場面: パンくずを増やさない（2 階層しか無い）

### 12-12. 地図のピンと区画（L1、新規）

- 地: `--background-1`。架空の村の道は `--border-strong` の 2px の線、区画は 4 列 × 3 行の長方形で枠 1px `--border-strong`、角 0
- 区画の塗り: 判断なし＝なし、収穫可能＝`--status-ready-soft`、収穫済＝`--status-done-soft`
- ピン: 区画の中央に番号のラベル（「A-03」、0.9rem 太字、左右 8px、高さ 32px、角 4px）。地は 判断なし＝`--surface`＋枠 `--border-strong`・文字 `--text-1`、収穫可能＝`--status-ready`・白、収穫済＝`--status-done`・白
- 未確定の印: ピンの右上に 12px の円（地 `--pending`、縁 2px `--pending-line`）。文字での説明は地図の下の凡例と一覧の行に（P3）
- 押せる: 区画全体が圃場ページへのリンク（押せる面は区画の大きさ。最小でも 56px になるよう地図の最小の高さを決める。§9）
- 凡例: 地図の下に 1 行の文字（印 3 つ＋「● 未確定あり」）。地図の中には置かない
- 使わない場面: 実在の地図タイル（P15）、撮影位置（K6）、集計の数字

### 12-13. 判断の入力（L1、新規）

- 並び: ①「収穫可能」「収穫済」の切り替え 2 つ（`.button-toggle`、横並び、どちらか 1 つ、`role="radiogroup"`）→ ②理由の選択肢 5 つ（`.button-toggle` の縦並び、複数可、`aria-pressed`。`STATUS_REASONS` の順）→ ③メモ（textarea、「あと n 字」）→ ④根拠の写真（選べる格子、「5 枚まで」）→ ⑤主ボタン「判断を残す」

- 使わない場面: 未確定の写真を根拠に選べるようにしない（その圃場の確定済みだけ。T12）。理由を必須にしない（0 個でよい。T12）

### 12-14. 判断の履歴の行（L1、新規）

- 見た目: 面、左線 6px（収穫可能＝緑、収穫済＝灰）。1 行目に 印＋日時（「2026年7月21日 14:05」）、2 行目に理由（「穂の色・黄色い穂の割合」。無ければ `--text-3` で「理由の記録なし」）、3 行目にメモ（全文。200 字まで）、4 行目に根拠の写真（格子の小さい版、最大 5 枚、押すと開く）、右下に「取り消す」（小）
- 取り消し済み: 左線なし、枠 dashed、文字 `--text-3`、印 `.badge-revoked`、「取り消す」は出ない。並びはそのまま（履歴は消さない）
- 使わない場面: 取り消した行を隠さない。端末 ID を出さない（privacy.md）

### 12-15. 引き継ぎメモ（L6、新規）

- 見た目: `HandoverNote.blocks` を段落として並べる。文の末尾に**引用の印**（`[1]`、`[2]`。`--brand` の文字、下線、押せる。1 つの文に複数可）。引用の無い文は `--text-3` で、末尾に `.badge-revoked` と同じ見え方の印「根拠なし」
- 引用の印を押すと、その段落の直下に `records[n].text`（例「[判断] 2026-07-21 収穫可能。理由: 穂の色」）が面（情報）で開き、元の記録（履歴の行か写真）へのリンクを持つ。もう一度押すと閉じる。`details/summary` でなくボタン＋`aria-expanded`（印が文中にあるため）
- 上に「作った日時・モデル」を `.note` で 1 行（「2026年11月6日 作成」。モデル名は `CLAUDE_MODEL` の値）。管理者には「作り直す」（副ボタン。1 日の上限に達したら disabled と文）

### 12-16. 状態の文（読み込み・空・誤り）

- 読み込み: `.note`「読み込み中…」を一覧の位置に（骨組み（skeleton）は作らない。12 圃場・50 枚の規模で 1 秒前後と推定）

- 誤り: `panel-alert` で 1 文＋やり直す操作（更新ボタンが同じ画面にあるならボタンは増やさない）
- 使わない場面: トースト、全画面の覆い、スピナーだけ
