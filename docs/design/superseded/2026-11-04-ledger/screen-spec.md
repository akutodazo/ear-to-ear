### 0-1. ページの枠

```
┌──────────────────────────────┐ ← body: --background-2
│ ← トップへ                   │ ← .back-link（トップ以外）
│ 見出し（h1）  補足（.note）  │

- 左右 16px、上下 24px（DS §5-1）。ナビゲーションの帯・ハンバーガーは作らない（画面は 4 つ、階層は 2 段。入口はトップ）
- 役割の表示: 管理者の端末では見出しの下に `.note.note-ok`「管理者として入っています」（既存）。委員にはなにも出さない（合言葉なしで見られる。K5）

### 0-2. 5 つの状態の出し方（DS §12-16）

| 状態 | 出し方 |
|---|---|
| 読み込み | 一覧の位置に `.note`「読み込み中…」。更新ボタンは busy。前の内容があるなら前の内容を残したまま（消して白くしない） |
| 空 | `.note` で「何も無い」＋「次にすること」の 1 文 |
| エラー | `panel-alert` で「何が起きた。どうする」。やり直す操作が同じ画面にあるならボタンを増やさない |
| 完了 | 押した所の近くに `.note.note-ok`。送った後のまとめだけ `panel-ok`（DS §7-4） |
| 通常 | 下の各画面 |

### 0-3. 合言葉の入力（共通の部品。DS §12-8 情報の面 ＋ §12-2）

```
┌ panel（情報）─────────────────────┐
│ 送るには合言葉が要ります。入れると、│ ← lead（画面ごとに差し替え）
│ そのまま送り直します。              │
│ 合言葉                             │
│ [________________________]  ← password│
│ 合言葉が違います          ← role=alert（あれば）│
│ [ 入って送る ]            ← 主ボタン│
└────────────────────────────────────┘
```

- 出るのは「送って 401」「管理者として入るを押した」「確定・変更で 401／403」のときだけ（11-03 決定）。出たら画面の中へ動かし、欄に focus（既存）。文: `LOGIN_MESSAGES`（既存）
- 回数の上限（429）の文「何度も間違えたので、10分ほどおいてからもう一度」は欄の直下（既存）。ボタンは押せるまま（サーバーが止める）

## 1. `/` トップ

### 目的
- L0: 「写真を送る」「新着を見る」への入口。ホーム画面に追加したときの最初の画面
- L1: それに加えて、12 圃場の状態（判断の色、未確定の有無）が一目で分かり、圃場ページに入れる

### 情報の優先順位
1. 写真を送る（委員が畑で開く最初の画面）
2. 新着を見る
3. （L1）圃場ごとの状態と、圃場ページへの入口
4. 副題「穂から穂へ、写真と判断をつなぐ」（11-02 決定。入口の邪魔をしない大きさ）

集計の数字（未確定 n 枚、判断済み n 圃場）はトップに置かない（spec §7「数字は控えめに」、DS §1 のやらないこと）。

### レイアウトと部品

**L0（今）**: `h1`「ear-to-ear」＋副題 ＋ 主ボタン「写真を送る」＋ 副ボタン「新着を見る」（既存のまま。変えない）

部品: 主・副ボタン（DS §12-1）、更新の行（§12-9）、地図のピンと区画（§12-12）、印（§12-3）、一覧の行（新規。`li > a` で 56px、左に番号 `.label`、名前 `.note`、右に印と「● 未確定」の文字）。

地図の高さ: スマホで `min(55vh, 420px)`、最低 320px（区画 1 つが 56px 以上になる。4 列 × 3 行で左右 16px なら 360px 幅で区画は約 80px）。

データ: `GET /api/fields/summary`（`FieldSummary[]`。`latest` の `status` で色、`hasUnconfirmed` で ●）。圃場の名前と地区は `src/data/fields.json`。

### 操作と遷移
- 「写真を送る」→ `/upload`、「新着を見る」→ `/recent`
- 区画（地図）か一覧の行 → `/fields/[id]`
- 「更新」→ summary を読み直す。自動更新はしない（spec §7 と同じ方針）
- 地図はドラッグ・ズームしない（区画は 12 個で全部見える。Leaflet を使うなら `dragging: false, zoomControl: false, scrollWheelZoom: false`。素の SVG でもよい。判断は実装時）

### 状態

| 状態 | 見え方 |
|---|---|
| 通常 | 上のとおり |
| 読み込み（初回） | 入口 2 つは即出す。地図は区画の枠だけ（塗りと印なし）、一覧の位置に「読み込み中…」 |
| 空（判断も未確定も無い） | 地図は枠だけ、一覧の印はすべて「判断なし」。空の文は出さない（12 圃場は必ずある） |
| エラー（summary が読めない） | 地図は枠だけ、一覧の上に `panel-alert`「圃場の状態を読み込めませんでした。更新を押してください」（仮）。一覧の行自体は `fields.json` から出し、印だけ無し（入口としては使える） |
| 完了 | 該当なし |

### スマホと広い画面
- スマホ: 入口 2 つ → 地図 → 凡例 → 一覧の順に縦に。地図の後に 40px
- 広い画面: 入口は見出しの行に横並び。地図（左 3/5）と一覧（右 2/5、地は `--background-1`、枠 1px）。一覧は地区の見出しごと

### 長文・件数増
- 圃場は 12 で固定（`generateStaticParams`）。増えても一覧は行が増えるだけ。地図は 4 列 × 3 行が前提で、13 以上は `fields.json` を変えるときに列数を決める
- 圃場の名前（「北の1」）が長くなっても `.note` で折り返す。番号は折らない

### 実装時の確認項目
- [ ] 360px 幅で入口 2 つが最初の画面に入る（地図より上）
- [ ] 区画とピンの押せる面が 56px 以上。区画の塗りと印は文字（一覧と凡例）でも分かる
- [ ] summary が 404／失敗でも入口と一覧が出る
- [ ] 座標は `fields.json` だけ。撮影位置・距離は一切出ない（K6）。地図タイルを読まない（P15）
- [ ] 凡例の印と一覧の印が DS §12-3 の同じクラス
- [ ] キーボードで区画・行に順に focus でき、`--focus-ring` が見える

## 2. `/upload` 写真を送る

### 目的
委員が畑で、写真を選んで送る。候補の番号と撮影日を確かめ、分かるときだけ番号を選ぶ。合言葉は要るときだけ入れる。

### 情報の優先順位
1. 写真を選ぶ／送る（操作）
2. 写真ごとの 候補（「A-06（約50m）」）と撮影日
3. 送った結果（写真ごと、全体のまとめ）
4. 「撮影した場所は、この端末の外に出しません」の説明（既存。K6 の約束を目に見える所に）

### レイアウトと部品（既存の構成。変える所は ★）

```
┌──────────────────────────────┐
│ ← トップへ                   │
│ 写真を送る                   │
│ 撮影した場所は、この端末の外に│ ← .note
│ 出しません。送るのは近い畑の番│
│ 号だけです。                 │
│ [     写真を選ぶ     ]       │ ← label.button-primary > input[type=file]（2 枚目以降は「写真を足す」）

│ │ □□□□□□□□□□□□□□□□□□□□□ │  │ ← 4:3

★ 変える所（DS §13 の S3・S4・S5 が当たる以外は無し）: 送った後のまとめの地を `--status-ready-soft`、カードの角 8px。文・並びは変えない（11-03 の実機で確認済み）。

### 操作と遷移
1. 「写真を選ぶ」→ 端末の写真選択（JPEG、複数）。選んだ写真ごとにカードが増え、撮影日「読み取り中…」→ 値
2. 「外す」→ カードが消える（1 段。戻せる: 選び直せばよい）
3. 「送る（n枚）」→ 帯のボタンが busy「送っています…（k/n枚）」。写真ごとに結果の文。401 なら合言葉の入力が送るボタンのすぐ上に出て、入れると自動で送り直す
4. 送り終わると `panel-ok` のまとめが画面の中へ（250ms）。「新着を見る」→ `/recent`、「続けて送る」→ 送り済みのカードを消して写真を選ぶ所へ
5. 失敗した写真は「送る」で送り直せる（failed は sendable）

### 状態

| 状態 | 見え方 |
|---|---|
| 通常（写真なし） | 説明＋「写真を選ぶ」だけ。帯なし。空の文は出さない（ボタンが次の行動） |
| 読み込み（写真の読み取り） | 撮影日「読み取り中…」、候補の行は出さない。送るボタンは選べる写真が 0 なので帯が無い |
| 送っている | 帯のボタン busy、各カードの select と「外す」が消える、結果の文「送っています…」（既存の `ItemStatus`） |
| 完了 | 写真ごとに `.note-ok`「送りました」、全体のまとめ `panel-ok`（文は `sendSummaryLabel`） |
| 同じ写真 | カードの結果 `.note`「送り済み（同じ写真）」、まとめに「1枚は同じ写真がもう送られていました」 |
| エラー（写真ごと） | `.note-alert` に `OUTCOME_LABELS` の文（「つながりませんでした。電波のよい所でもう一度送ってください」など）。「外す」が戻る |
| エラー（開けない写真） | 写真の所に「開けない写真」、情報は出さない、送る数に入れない |
| 合言葉 | §0-3。入れると自動で送り直し、合言葉の面は消える |

### スマホと広い画面
- 幅はどちらも `--page-narrow`（640px）。PC で送る場面は少なく、1 列のままで足りる
- 写真の高さ: 幅 360px で 4:3 なら 270px。1 画面に写真 1〜2 枚。枚数が多いときに帯が下に付いてくる（既存）

### 長文・件数増
- 写真 10 枚以上: カードが縦に続く。帯の「送る（n枚）」で枚数が分かる。全部の写真を上に戻って確かめなくてよいように、送った後のまとめは**一番下**（帯のすぐ上）に出し、そこへ動かす（既存の方針）
- 候補の表示「A-06（約50m）」は折らない。「ほかの候補: A-07・A-02」は折れてよい
- select の選択肢は 12 圃場（「A-01 北の1」）。増えても `optgroup` で地区ごと（確定フォームと同じ `assignmentOptionGroups` の並びに合わせるかは実装時）

### 実装時の確認項目
- [ ] 送る meta に座標・距離が無い（既存のテスト。K6）。距離は「候補:」の行にだけ出る
- [ ] 帯の高さぶん本文の下に余白があり、最後のカードの「外す」が帯に隠れない
- [ ] 合言葉の面が出たとき欄に focus が移り、`scroll-margin-bottom` で帯に隠れない
- [ ] busy のボタンの文字が薄くならない（`aria-busy` のとき不透明度 1）
- [ ] 送った後のまとめが `prefers-reduced-motion` で動かずに出る
- [ ] 麦色がこの画面に出ない（未確定の印は新着にだけ）

## 3. `/recent` 新着

### 目的
委員が、送った写真が届いたか、ほかの委員の写真が来ているかを見る。管理者が、未確定の写真に番号を付ける（確定・変更）。

### 情報の優先順位
1. 写真ごとの 状態の印（未確定／確定）と番号（「推定 A-06」「A-03」）
2. 撮影日
3. 写真（小さく。手がかり）
4. 更新と「〜時点」、未確定の枚数、未確定だけ見る
5. （管理者）確定・変更のフォーム
6. 管理者として入る（委員には小さく、下に）

### レイアウトと部品

```
スマホ                                   広い画面（960px〜、1040px）
┌──────────────────────────────┐         ┌──────────────────────────────────────┐
│ ← トップへ                   │         │ 新着     管理者として入っています        │
│ 新着                         │         │ [ 更新 ] 14:05 時点  [ 未確定だけ見る ] 未確定 3枚│
│ 管理者として入っています      │ ← admin ├──────┬─────────────────┬─────────────┤
│ [ 更新 ]  14:05 時点         │         │ □160 │ [未確定] 推定 A-06│ 番号を決める │
│ [ 未確定だけ見る ] 未確定 3枚 │         │      │ 2026年7月21日     │ [A-06 中の2▾]│
│ ┌ card-row card-pending ───┐ │         │      │                   │ [ 確定する ] │
│ ║ □120 │ [未確定] 推定 A-06 │ │         ├──────┼─────────────────┼─────────────┤
│ ║      │ 2026年7月21日      │ │         │ □    │ [確定] A-03       │ [A-03 北の3▾]│
│ ║ 番号を決める（管理者）    │ │ ← admin │      │ 2026年7月20日     │ [ 変更する ] │
│ ║ [ 推定 ▸ A-06 中の2   ▾ ] │ │         └──────┴─────────────────┴─────────────┘
│ ║ [ 確定する ]  確定しました│ │
│ └──────────────────────────┘ │
│ ┌ card-row ────────────────┐ │
│ │ □120 │ [確定] A-03        │ │
│ │      │ 2026年7月20日      │ │
│ └──────────────────────────┘ │
│ ┌ card-row card-alert ─────┐ │
│ ║ □    │ [確定] 番号なし    │ │ ← データの矛盾（隠さない）
│ └──────────────────────────┘ │
│ [ 管理者として入る ]         │ ← 委員の端末だけ（小）
└──────────────────────────────┘
```

部品: 更新の行（DS §12-9）、切り替え（§12-1）、写真の行（§12-4）、印（§12-3）、確定フォーム（既存 `assignment-form`: ラベル「番号を決める（管理者）」、select は「推定」→ 地区の `optgroup`、ボタン「確定する」／「変更する」（`assignButtonLabel`）、結果の文）、合言葉（§0-3、lead「番号を決めるには、管理者の合言葉が要ります。」、ボタン「管理者として入る」）。

★ 変える所: 写真の行の角 8px（S5）、未確定の左線を `--pending-line`（濃い麦色。印の地は `--pending` のまま）。広い画面の 3 列（S10）。

### 操作と遷移
- 「更新」→ `GET /api/photos/recent` を読み直す。ボタン busy「読み込み中…」、一覧は前の内容のまま、読めたら差し替えと「HH:MM 時点」
- 「未確定だけ見る」→ 絞り込み（`aria-pressed`）。並びは変えない。絞って 0 枚なら「未確定の写真はありません」（既存の文を一覧の位置に）
- 行の写真を押す → 元の大きさで開く（新しいタブ。`/fields/[id]` と同じ）。**確定済みの行の番号を押すと圃場ページへ**（新規・仮。番号 `.label` を `a` に。未確定の行は番号が無いのでリンクにしない）
- （管理者）select で番号 → 「確定する」→ busy「送っています…」→ 結果の文（`assignOutcomeLabel`）。成功で行の印が「確定」に変わり、左線が消える。403／401 なら合言葉の面
- 「管理者として入る」→ 合言葉の面が出る（既存）

### 状態

| 状態 | 見え方 |
|---|---|
| 通常 | 上のとおり。新しい順 |
| 読み込み（初回） | 更新ボタン busy、一覧の位置に「読み込み中…」 |
| 読み込み（2 回目以降） | 前の一覧を残したまま、ボタンだけ busy |
| 空 | `.note`「まだ写真がありません。「写真を送る」から送れます」（仮）＋ 副ボタン「写真を送る」 |
| 空（絞り込み） | 「未確定の写真はありません」（既存） |
| エラー | `panel-alert`「新着を読み込めませんでした。電波のよい所で更新を押してください」（仮）。前の一覧は残す |
| 完了（確定） | フォームの下に `.note-ok`「確定しました」（既存の `assignOutcomeLabel`）。行の印が変わる |
| エラー（確定） | フォームの下に `.note`（`assignOutcomeLabel` の失敗の文）。422（一覧に無い番号）は select で選べないので起きない前提 |
| 矛盾（確定なのに番号なし） | `card-alert`＋`badge-alert`「確定」＋「番号なし」（既存。隠さない） |

### スマホと広い画面
- スマホ: 行は 写真 120px ＋ 文字、管理者のフォームは行の下に全幅
- 広い画面: 写真 160px、文字、フォーム（右の列、幅 280px 前後）の 3 列。1 画面に 6〜8 行（管理者が上から順に確定する作業）

### 長文・件数増
- 既定 50 枚、最大 200（`RECENT_LIMIT_*`）。50 枚なら行の高さ約 150px で 7,500px、スクロールで足りる。200 枚に増やす「さらに読む」は**作らない**（API の `limit` はあるが、画面の仕組みを増やさない。要るなら「未確定だけ見る」で絞る）
- 「推定 A-06」「2026年7月21日」は折らない。行の文字は 3 行まで
- 管理者の select の文字「A-06 中の2」は 12 圃場で収まる

### 実装時の確認項目
- [ ] 未確定の行は 左線＋印の文字「未確定」の両方（色だけに頼らない）
- [ ] 更新中に一覧が消えて白くならない
- [ ] 確定の後、同じ写真が二重に出ない。印と左線が同時に変わる
- [ ] 委員の端末（Cookie なし・member）に確定フォームが出ない。`GET /api/session` の形が違っても管理者扱いにしない（既存）
- [ ] 端末 ID・委員が選んだ番号（`chosenFieldId`）を画面に出さない（privacy.md、11-03 不承認）
- [ ] 960px で 3 列になり、1040px を超えて広がらない。320px で横スクロール無し

## 4. `/fields/[id]` 圃場ページ（L1・L6）

### 目的
1 つの圃場について、確定済みの写真を撮影日ごとに見つけ、判断（収穫可能／収穫済）を理由と根拠つきで残し、履歴をたどり、引き継ぎメモを読む。

### 情報の優先順位
1. 圃場番号と名前（見出し）と、**今の判断**（最新の有効な判断の印）
2. 判断を残す（委員以上の主な操作）
3. 写真（撮影日ごと。日付不明は最後）
4. 判断の履歴（理由・メモ・根拠。取り消しも）
5. 引き継ぎメモ（L6。来年の委員向け。収穫期には読まない）

順番の理由: 収穫期に開く人は「今どうなっているか」と「判断を残す」が目的。引き継ぎメモは翌年に読むので一番下。ただし見出しの直下に「引き継ぎメモへ」の文字のリンクを 1 つ置く（長いページを飛べる）。

### 操作と遷移
1. 格子の写真 → 元の大きさで開く（既存）
2. 「収穫可能」「収穫済」→ どちらか 1 つ（`radiogroup`）。選ぶと「判断を残す」が押せる
3. 理由 → 複数可、0 個でもよい。「その他」でもメモは任意（T12）
4. メモ → 入力のたびに「あと n 字」。201 字以上で文字が `--assertive`、`aria-invalid`、送れない
5. 根拠の写真 → 格子で選ぶ（選んだ順に 1〜5 の番号が角に）。6 枚目は選べない（残りが薄くなり、格子の上に「5枚まで選べます」）
6. 「判断を残す」→ busy「残しています…」（仮）→ 成功で `panel-ok`「判断を残しました」（仮）、入力を空に戻し、履歴の先頭に行、見出しの最新の印が変わる。401 → 合言葉の面（入れたら残し直す）。422 → ボタンの直下に `role="alert"`（表）
7. 履歴の「取り消す」→ 2 段（DS §7-3）: 1 回目で「もう一度押すと取り消します」（`.button-danger`）、5 秒で戻る。2 回目で `DELETE` → 行が取り消し済みの見え方に。見出しの最新の印は summary を読み直して更新（または履歴から計算）
8. 「引き継ぎメモへ」→ ページ内リンク。引用の印 `[n]` → 直下に記録の面、「この記録を見る」→ 履歴の行か写真へページ内で移動（`id` を付ける）。「作り直す」（管理者）→ busy「作っています…」（仮）、成功で本文が差し替わる。429 → 「今日の上限に達しました。明日もう一度」（仮）。502 → 「作れませんでした。時間をおいてもう一度」（仮）

### スマホと広い画面
- スマホ: 見出し → 判断を残す → 写真 → 履歴 → 引き継ぎメモ の 1 列。「判断を残す」の主ボタンは入力の末尾（下に固定の帯にはしない: 入力の途中で押すと誤りになるため。ただし根拠の格子が長くなるなら帯にする。実装時に判断）
- 広い画面: 左（写真）と右（判断を残す → 履歴）の 2 列、引き継ぎメモは下に全幅（文章は 640px に止める）

### 長文・件数増
- 写真: 1 日 20 枚でも格子は折り返すだけ。撮影日が 20 日分でも見出しが並ぶだけ。日付への飛び先は作らない（12 圃場 × 3 週間の規模）
- メモ 200 字: 約 6 行（33 字/行）。履歴の行で全文を出す（省略しない。根拠をたどる場面で省略は困る）
- 理由 5 つの文字列「農協の判定で中止（砕けなどの傷）」は 17 字。切り替えのボタン（56px）の中で 1 行に入る（360px で左右 24px の余白を引いて約 17 字。入らなければ括弧の前で折って 2 行、高さは伸びる）
- 履歴が 20 件: 取り消し済みも全部出す。「古い判断を見る」の折りたたみは作らない（たどれることが中心）
- 引き継ぎメモ: 数段落。引用の面は 1 度に 1 つだけ開く（複数開くとページが伸びる）

### 実装時の確認項目
- [ ] 見出しの最新の印が `GET /api/fields/summary` の `latest` と一致する（取り消しを除いた最新）
- [ ] 根拠に選べるのは**その圃場の確定済み**の写真だけ。未確定の写真はこのページに出ない
- [ ] 「判断を残す」が 1 画面に 1 つの主ボタン。「作り直す」「取り消す」は副・小
- [ ] 取り消しが 2 段で、1 段目が 5 秒で戻る。モーダルを出さない
- [ ] 取り消した判断が消えない（dashed の枠と `--text-3`）
- [ ] 引用の無い文が `--text-3`＋「根拠なし」で、引用のある文と見分けがつく。引用の印がキーボードで押せ、`aria-expanded` を持つ
- [ ] Claude の文を言い換えない・飾らない。モデル名と作成日時を出す
- [ ] 360px で理由の切り替えが 2 行になっても押せる面が 56px 以上
- [ ] 文中の日付・番号が折れない（`nowrap`）
