# 提出前の全体の点検（11/7、本人向けの手順）

AGENTS.md §3「提出前の全体の点検（11/7）は、書いた会話を見ていない別の Claude Code のセッション（Opus）でレビューする」の手順。11/8 の昼に一度提出するので、**11/7 のうちに点検と直しを終える**。11/7 の夕方以降は新しい段に手を付けない（AGENTS.md）。直すのは点検で出た指摘だけにする。

## 0. いつ・何を
- 11/7 の昼までに main を止める（入れたい PR をマージし終える）。点検の対象は**その時点の main のコミット 1 つ**。番号を控える
- 点検の後に入れる PR は「点検の指摘の直し」だけ

## 1. 人が回す検査（本人、手元）
main を最新にしたフォルダで、1 つずつ実行する。

```bash
npm run check
```

```bash
node scripts/check-history.mjs
```

- `check-history.mjs` は、すべてのコミット（手元の枝と origin の枝）に一度でも入ったファイルを、今の安全検査と同じ判定（`scripts/safety-rules.ts`）で見る。1 分ほどかかる。秘密の値は表示しない
  - 11-06 に 211 コミット・895 版で OK。偽の API キーと `.dev.vars` を一度入れて消した使い捨てのリポジトリで、両方を見つけることも確かめた
- 履歴に見つかったら、消すには履歴の書き換え（force push）が要る。main は force push を禁止しているので、**見つけたら止めて本人と先輩で決める**。書き換えても GitHub の古い参照に残ることがあるので、キーならまず無効にする

## 2. 別のセッションの点検（Opus、書いた会話を見ていない）
1. リポジトリの外に空のフォルダを作り、GitHub の main を取ってくる（手元の未 push の枝を混ぜない）

   ```bash
   git clone --depth 1 https://github.com/akutodazo/ear-to-ear.git <空のフォルダ>
   ```

2. そのフォルダで、新しい Claude Code のセッションを Opus で始める（Claude のデスクトップのアプリで新しいセッションを作るか、`claude --setting-sources project`）。手元の設定とメモリーを混ぜない
3. 渡す文面はこれだけ（背景・経緯・この手順書の §3 は渡さない）:

   > 提出前の全体の点検をしてください。AGENTS.md と docs/spec.md を読んでから、リポジトリ全体を見てください。指摘は「止める／直す／見送ってよい」に分け、場所・理由・直し方の案を付けて、docs/reviews/2026-11-07-final-review.md に書いてください。コミットと push はしないでください。

4. 結果のファイルを本人が読み、手元のリポジトリの `docs/reviews/` に写して PR に入れる

## 3. 人にしか確かめられないこと（点検役には渡さない）
| 何 | どう確かめる |
|---|---|
| `public/demo/` の画像が実写真でない | 開いて目で見る（安全検査はメタデータが無いことまでしか分からない。AGENTS.md §1-5） |
| 実家の写真の扱いが決定どうし食い違っていない | K10（開発用とデモ用の環境・動画に実在の写真を入れない）と、11-04 夜の決定（デモの写真は実家の写真を dev の R2 に入れる、動画に写る）を読み比べる。食い違うなら、どちらを正とするかを `docs/decisions.md` に書いてから提出する |
| demo の環境に入るデータ | 審査員が開いたときに見える記録が架空のものだけか（#130） |
| GitHub の設定 | Secret scanning と Push protection がオン、Pages・Wiki が使われていない（spec §10） |
| ライセンス | MIT にするか先輩と決める。決まるまで LICENSE は置かない（spec §10） |
| 動画 | 期間中に作ったもの・架空のデータだけが映る。冒頭 1 分で「A が送る → B の画面で見える」（合格条件 11） |

## 4. 指摘の扱い
- **止める**: 提出の前に必ず直す。直せないなら、その機能を提出版から外す
- **直す**: 11/8 の昼の提出までに直す。直さないなら、理由を PR の本文に書く
- **見送ってよい**: 提出の後に回す。Issue にする
- 採否は `docs/decisions.md` か、Claude の記憶のメモ（本人の手元）に残す
