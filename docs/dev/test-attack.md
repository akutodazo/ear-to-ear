# テストを攻撃する Claude（RED の凍結前にズルで破らせる）

Issue: akutodazo/ear-to-ear#17。**状態: 採用（11-03 本人決定）。本人・先輩どちらの無人運転でも、凍結の前に行う**（AGENTS.md §5、ハーネス v0.5）。

RED を凍結する前に、仕様を知らない別のセッションに「最小のズルで全件通せ」と頼む。通ったらテストが弱い。人が直してから凍結する。

## 手順
1. RED をコミットする
2. 攻撃役のフォルダを作る（役の一覧は `docs/dev/roles.md`）

   ```bash
   node scripts/roles/build-brief.mjs attacker --impl <実装> --test <テスト> --out <空のフォルダ>
   ```

3. `work` に Git とテストの実行に要るものを足し、檻の中で起動する（`docs/dev/cage.md`。`CAGE_ALLOW` は実装のファイルだけ）。モデルは Sonnet
4. 報告を人が読む。仕様の範囲の指摘だけテストにする。単体テストで測れないもの・仕様に無いものは、理由を残して入れない
5. 手抜きの実装は捨てる（コミットしない）。テストを足したら 2 に戻る。全件通る手抜きが書けなくなるか、残りが仕様の外だけになったら凍結する

## 「穴を突く実装」（docs/dev/holes.md）との違い
| | この手順 | 穴を突く実装（#22） |
|---|---|---|
| 渡すもの | テストと空の実装だけ | 凍結テスト・型・設定・合格条件・決定の文 |
| 頼むこと | 最小のズルで全件通す | 条項ごとに、テストを通したまま条項を破る |
| 見つかるもの | テストだけでは仕様が伝わっていない所 | 仕様の条項をテストが縛っていない所 |
| いつ | RED の凍結前 | 凍結後、GREEN の前 |

狙いが違うので、どちらかに統一はしない。人の時間が足りないときは、短く回せるこの手順を先にする。
