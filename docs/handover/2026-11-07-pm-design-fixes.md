## 画面の確かめ方（この PC で初めて動かすとき）

`npm run dev`（`next dev`）には Worker の API が無く、判断や写真が読み込めない。前の PC の差し込みの台本も使えない。次のとおり、ブラウザの中で架空の値を入れる。合言葉は入れない。

1. `.claude/launch.json` が無ければ、`npm run dev`・ポート 3000 の設定を一時的に作り、`preview_start` で起動する。終わったら止めて、作った設定を消す（コミットしない）。
2. `http://localhost:3000/` を開き、375×812 にする。
3. ページの中で `window.fetch` を差し替え、下の応答を返す。`/api/` 以外は元の `fetch` に渡す。
4. 再読み込みすると差し替えが消えるので、以後は画面の中のリンクか `window.next.router.push()` で移る。

| 呼び出し | 返す値 |
|---|---|
| `GET /api/fields/summary` | `{ fields: [{ fieldId, latest, hasUnconfirmed }] }`。`latest` は `StatusEvent` か `null` |
| `GET /api/fields/:id/status-events` | `StatusEvent` の配列 |
| `GET /api/photos?fieldId=:id` | `UploadedPhoto` の配列 |
| `GET /api/photos/recent?limit=n` | `UploadedPhoto` の配列 |
| `GET /api/session` | `{ role: "admin" }` または `{ role: "member" }`。未ログインは 401 |

- 型は `src/types/index.ts` のとおり。写真の `state` は `"unconfirmed"` か `"confirmed"`。ここを別の値にすると、新着の表示が食い違って偽の不具合に見える。
- `/api/photo-files/:id` の画像は、`MutationObserver` で `img` の `src` を canvas で描いた合成の絵に置き換える。実写真を使わない。
- データはすべて架空。日付は 2026 年 7 月にする。
- ブラウザのペインが隠れていると、スクリーンショットが画面の左上 75% しか写らないことがある。`document.body` に `transform: scale(.66)`、`transform-origin: 0 0` を付けて写す。**大きさを測るときは外す**（測った値まで縮むため）。
- 地理院タイルが読み込めないときは、サイトの許可を本人に頼む。
- 開発中だけ出る左下の丸い印（Next.js の表示）は、本番には出ない。

## 本番の修正の決まり

- `main` に直接コミットしない。作業の枝を切り、1 つの PR に 1 つの関心事にする。
- この PC の権限やフックで push・`gh` が止められたら、回避せず本人に聞く。
- 実装の順番と PR の分け方:
  1. 左上の名前・メモのボタン・立場の入口
  2. 順番の一覧（#3〜#6）
  3. 4 画面への分割（#1・#8）
  4. 区画（#9）
- 区画の PR は `AGENTS.md` を変えるので、**先輩の確認を待つ**（CLAUDE.md の例外）。ほかの PR を止めないよう分ける。
- 判定を変えるロジックは、テスト（RED）と実装（GREEN）を別のコミットにする。テストを手抜きで通さない。
- 静的書き出しなので、新しい動的ルートには `generateStaticParams` が要る。Next.js を書く前に `node_modules/next/dist/docs/` の該当ガイドを読む。
- 画面の文書（`docs/design/screen-spec.md`、`docs/spec.md` §7）を実装と同じ PR で直す。
- 終わったら `npm run check` の出力を見せる。実画面も 375px で確かめ、確かめ方と未確認のことを分けて報告する。
