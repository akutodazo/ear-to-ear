# 仮説の台帳（期限と既決の代替）

Issue: akutodazo/ear-to-ear#23。**状態: 提案（11-02）。期限と代替は本人が決める。この初版の期限は「仮」。** 採用するときは AGENTS.md §5 に「期限切れの仮説に依存するパケットは条件つき」を足す（先輩の確認の後、別 PR）。

## 崩す前提
「未確認の前提の上に作っても、後で確かめれば済む」。期限が来たか否定されたら、**作らない方へ倒れる**のを既定にする。代替は人が先に決め、Claude は依存箇所の追跡と切り替え差分の起草だけを行う。差分の適用は人が承認する。

## 区別
- **事実**: 実機や記録で確かめたこと（出どころと日付を書く）
- **仮説**: 未確認のこと。父の一言で「確認」になっても、一人の報告であって実機の記録とは重みが違う。出どころの種類を書く
- **決定**: `docs/decisions.md` の K 番号。仮説ではない

## 毎日の終わりにすること（本人、10分）
1. 新しい証拠（父の回答、実機の記録、PR）を台帳の「状態」に書く。出どころと日付を付ける
2. 期限を過ぎた仮説を「期限切れ」にする
3. 「否定」「期限切れ」になった仮説があれば、別セッションの Claude に台帳・spec・README・TASKS を渡し、**代替への切り替え差分**をドラフト PR として起草させる。依存する箇所の列挙も出させる
4. 人が差分を読み、承認するか閉じる。承認した差分だけがマージされる

## 範囲
| 誰が | 何を |

| Claude | 依存箇所の追跡、切り替え差分の起草 |
| プログラム | （期間中は無し。価値が出たら、台帳の状態と README の印の突き合わせを CI に） |
| 人 | 代替の事前決定、証拠の記入、差分の承認 |

## 誤ったとき
- 依存の追跡漏れ・過剰: 不要な変更はドラフト PR を閉じるだけで戻る。台帳は git で版管理される
- 代替は人が先に決めているので、Claude の誤りは「どこを直すか」に限られる

## 既存の手法との関係
- 仮説駆動開発の kill criteria、PMBOK の assumption log、ADR の見直しトリガー（日付・指標・出来事）と同じ考え。ここで足したのは、「崩れたときの代替を先に決める」「期限切れで切り替え差分を起草する」「依存するパケットを条件つきにする」の3つ
- 探した範囲では、期限切れで切り替え差分を自動で起こす例は見つからなかった（無いとは言えない。新規性は未確認）

## 最小実験（P2、半日）
- 本人が P2 の依存箇所を封をして列挙する（15分）
- 別セッションの Claude に、台帳・spec・README・TASKS を渡し、「P2 が否定された」として切り替え差分を起草させる（30分）
- 比べる: 人の列挙に無い依存箇所の数、差分の誤りの数（人の手直しの時間）、起草の時間
- 成功: 人の列挙に無い依存が1つ以上あり、差分の手直しが10分以内
- 失敗: 依存の追跡が人の列挙と同じか少なく、差分の手直しが起草より時間を食う。失敗なら、台帳は表として残し、差分の起草は人がやる
