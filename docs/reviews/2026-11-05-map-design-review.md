# 地図の画面のデザインレビュー（2026-11-05）

- 対象: 枝 `feature/l1-map-leaflet`（`origin/main...HEAD`、最新 `70acceb`）の `/`（地図）
- 精査役: 書いた会話を見ていない別の Claude Code のセッション（Opus）
- 基準: `REVIEW-BRIEF.md`（最優先）、`AGENTS.md`、`docs/spec.md`
- 確かめ方: `npm run dev` → 内蔵ブラウザ 375×812。`demo-mock.js` で架空の判断と写真を差し込み、開いたとき（北地区）／圃場を押したとき（A-04・目安の A-03・写真の無い A-09）／縮小 2 段／地区の切り替え（中地区）を見た。文字の大きさ・区画の位置は画面の上で数値でも測った
- 注意: 開発サーバーなので左下の Next.js の「N」が下の帯に重なるが、本番には出ないので指摘から外した

## 全体の判定
**このまま進めてよい（止める指摘は無い）。** 開いた瞬間に目に入るのは航空写真と、道の向きにそろった帯状の区画のまとまりで、黄緑の塗りと金の輪郭が中央に来る。「最初の視線を畑に向ける」はおおむね達成している。
ただし「直す」が 7 件ある。特に **#1 地区の飛び**（選ぶ・閉じるで地図が動き、どこを見ていたか見失う）と **#2 選択と収穫可能が同じ黄緑**（目安の金も選ぶと消える）は、基準の中心（選んだ畑を見失わない／目安・収穫可能・選択中を見分ける）に関わるので、提出前に直したい。

## 指摘（重い順）

### #1 他の地区の畑を押すと地図が飛び、閉じると元の地区へ飛び戻る — 直す
- **どこ**: 地図全体。`src/app/home-client.tsx` の `district = selected?.district ?? districtChoice ?? districts[0]` と `fitKey={district}`、`src/components/map/field-map.tsx` の `fitIfNeeded`
- **何が問題か**: 北地区を開いた画面の下には南地区の帯（A-09〜A-12）も見えていて押せる。A-09 を押すと、地区が南に変わって地図が合わせ直され、押した帯が指の下から約 275px 上へ動く（A-09 の中心 y=628 → 353）。板の × で閉じると、`districtChoice` が空のままなので地区が北に戻り、地図がまた飛ぶ（y=353 → 628）。地区の選択欄も「南地区 → 北地区」に勝手に戻る
- **なぜ**: 基準 §3「選択後もどの場所を見ているか分かる」、§5「選んだ畑と表示された写真の対応を見失わないか」。押した物が動くと、板の写真がどの帯のものかを目で結べない
- **直し方の案**: (a) 畑を押したときは地図を動かさない（地区の表示だけ変える）。合わせ直すのは選択欄を変えたときだけにする。(b) 押した畑の地区を `districtChoice` にも入れ、閉じても地区を保つ。どちらか一方でも飛び戻りは消える。(a)＋(b) を推奨

### #2 「選択中」と「収穫可能」が同じ黄緑。目安の畑を選ぶと金の輪郭が消える — 直す
- **どこ**: `field-map.tsx` の `LIME` を塗り（ready）と選択の線の両方に使っている所、`lineStyle()` が `selected` を `benchmark` より先に判定する所
- **何が問題か**: 収穫可能の畑（A-04）を選ぶと、黄緑の塗りに黄緑の太線が重なり、隣の収穫可能の畑（A-03）との違いは線の太さだけになる。目安の A-03 を選ぶと、金の輪郭が黄緑の線に置き換わり、地図の上で「目安」は小さな文字だけになる
- **なぜ**: 基準 §3「目安・収穫可能・選択中は見分けられる」「色だけに依存しない」、§5「目安の畑と収穫可能な畑を見分けられるか」
- **直し方の案**: 選択は「色」ではなく別の手段で表す。例: 選んだ畑は白の太線＋外側に濃い影（いまの影を太く）、または選んでいない畑の塗りと線を少し弱める（選んだ畑だけが浮く）。目安の金の線は選んでも残す（選択の線を外側に重ねる二重線）

### #3 「目安の畑と見比べる」の先に、まだ見比べが無い。南地区には目安の畑も無い — 直す
- **どこ**: `src/components/map/selection-dock.tsx` の主ボタン（`/fields/${field.id}` へ）、`src/components/app-nav.tsx` の「見比べる」、`src/data/benchmarks.json`（北地区 A-03・中地区 A-07 だけ）
- **何が問題か**: 板の中で一番強い部品（濃い緑の全幅ボタン）が「目安の畑と見比べる」と約束するが、行き先の圃場ページは今のところその畑の写真だけで、目安の写真は出ない（`src/app` に benchmark を使う所が無い）。南地区の A-09 でも同じ文言が出るが、南地区には目安の畑が決まっていない
- **なぜ**: 基準 §3「畑の選択 → 最新写真 → 比較・収穫順へ、対象を見失わずに進める」、§4「目安の写真を固定し、比較対象を縦にスクロールする」。押した先で約束が果たされないと、つながりが切れる
- **直し方の案**: 見比べの画面ができるまでは、文言を行き先に合わせる（「この畑の写真を見る」）。目安の無い地区では「目安の畑と見比べる」を出さない。見比べの画面を作るなら、目安の写真が上に固定される形にしてから文言を戻す

### #4 下の帯の 3 つのうち 2 つが、開いた瞬間から灰色で押せない — 直す
- **どこ**: `src/components/app-nav.tsx`（「見比べる」は圃場を選ぶまで、「刈る順番」は常に `app-nav-disabled`、不透明度 0.45）
- **何が問題か**: 最初の画面で、下の帯は「地図」以外が薄い。押せない理由は見ても分からない。「見比べる」は畑を選ぶと濃くなるが、その関係は帯からは読み取れない。「刈る順番」は押しても何も起きない
- **なぜ**: 基準 §3「文字のメニューだけに機能の意味を背負わせない」、§5「どこがタップできるのか、自然に分かるか」。押せない物が画面の 2/3 を占めると「この画面ではまだ何もできない」と読める
- **直し方の案**: 「見比べる」は選んでいなくても押せるようにし、その地区の目安の畑から始める（#3 と合わせて）。「刈る順番」は作るまで帯から外すか、押したら「11/○ に追加予定」のように小さく返す。灰色の項目を並べたままにしない

### #5 一番大きく太い文字が、畑ではなく上下の帯にある — 直す
- **どこ**: `src/app/globals.css`。上の帯の地区の選択欄 18px 太字・「写真を送る」18px 太字・「ear-to-ear」18px 太字、下の帯 17.1px 太字（`.app-nav-item` 0.95rem）。地図の札は番号 12px・名前 14px
- **何が問題か**: 地図そのものは画面の約 85% を占め、視線は塗りのある帯に向かう。ただ文字の階層では、畑の名前より操作部品の文字が大きく太い。特に下の帯の「地図／見比べる／刈る順番」は、見出しのような重さで常に見える
- **なぜ**: REVIEW-BRIEF §2「情報の重要さと視覚的な強さを一致させる」「UI の文字や部品を見る画面になっている」
- **直し方の案**: 下の帯の文字を 13〜14px・普通の太さにし、現在地だけ太字にする。上の帯は「写真を送る」の枠を残しつつ 16px に。畑の名前（14px）が操作部品の文字より弱くならない釣り合いにする。一律の縮小ではなく「畑の名前 ≧ 操作の文字」を目安に

### #6 未確定の写真の白い点が、凡例にも画面のどこにも説明が無い — 直す
- **どこ**: `field-map.tsx` の `.map-label-dot`（A-02・A-08 の番号の横）、`src/components/map/map-legend.tsx`
- **何が問題か**: 点の意味は `title` 属性と読み上げ（aria-label）にしか無く、スマートフォンでは見る手段が無い。板を開くと「未確定の写真あり」と出るが、地図だけでは何の点か分からない
- **なぜ**: 基準 §3「記号・短い文字を組み合わせ」、spec §3 の L1「未確定の写真がある圃場に印」。印は意味が分かって初めて役に立つ
- **直し方の案**: 凡例に「● 未確定の写真」を 1 項目足す（凡例はいま 4 項目で 1 行に収まっていないので、2 行になるのは許容）

### #7 板の「□ 未確認」がチェックボックスに見える — 直す
- **どこ**: `selection-dock.tsx` の `.dock-status` と `.mark-none`（白地に灰色の枠の四角）
- **何が問題か**: 板の中では、白い四角＋太字「未確認」が「押すと確認済みにできる欄」に見える。押しても何も起きない。地図の上の未確認（塗りなし）は誤解しにくいが、板の中では文脈が変わる
- **なぜ**: 基準 §5「未確認を不可と誤解させないか」「アイコンに置き換えて分かりにくくなった所は無いか」。印を足したことで別の意味が生まれている
- **直し方の案**: 板では未確認の印を出さず、文字を普通の太さ・薄い色の「判断はまだありません」にする。または印を四角でなく細い線の輪（地図の輪郭と同じ形）にする

### #8 札の「■ 7/21」の日付が、何の日か分からない — 提案
- **どこ**: `field-map.tsx` の `labelHtml()`（「可」「済」を印に置き換え、日付だけ残した所）、板の「収穫可能 7/22」
- **何が問題か**: 7/21 は判断を記録した日だが、地図の上では「刈る予定の日」とも読める。収穫の順番を考える画面なので、予定日と読まれると誤解が大きい
- **なぜ**: 基準 §5「文字を消すだけ、アイコンに置き換えるだけで改善したつもりになっていないか」。「可」を消したことで日付の主語が無くなった。AGENTS.md「推定は推定と書く」
- **直し方の案**: 地図では日付を出さない（塗りで状態は分かる。日付は板で十分）か、板では「7/22 に収穫可能と判断」のように日付の意味を言う

### #9 板の写真が小さく、押しても何も起きない — 提案
- **どこ**: `selection-dock.tsx` の `.dock-photo`（96×96px、リンクなし）
- **何が問題か**: 畑を押した結果の主役は「最新の写真」だが、板の中で一番強いのは全幅の濃い緑のボタンで、写真は左の小さな枠。写真を押して大きく見ようとしても反応しない
- **なぜ**: REVIEW-BRIEF §1「タップすると、その畑の写真や情報を見られる」、§2「重要さと視覚的な強さを一致」
- **直し方の案**: 写真自体を圃場ページへのリンクにする。写真を横長（例 幅いっぱい×120px）にして、ボタンは写真の下に細く。あるいは写真の枠を 120px 程度に広げる

### #10 札・地区の選択欄の書体が Arial になっている — 提案
- **どこ**: `globals.css` の `.leaflet-container { font-family: inherit }` が `leaflet/dist/leaflet.css` に負けている（札の計算後の書体が `"Helvetica Neue", Arial`）。`<select>` も書体を受け継いでいない（Arial）
- **何が問題か**: 「A-01」のような英数字が Arial、「北の1」は日本語の書体になり、札の中で書体が混ざる。上の帯の「北地区」も周りと書体が違う
- **なぜ**: REVIEW-BRIEF §2「残る AI 感は『フォントの感じ』」、§3「癖の少ない日本語書体」
- **直し方の案**: `.field-map.leaflet-container` のように詳しさを上げて `font-family: inherit` を効かせる。`select, button, input { font: inherit; }` を足す

### #11 つながらないときの文言が、ボタンの名前と合っていない — 提案
- **どこ**: `src/hooks/use-field-map.ts` 40〜41 行目「『更新』を押してください」、`home-client.tsx` のボタン「もう一度読み込む」
- **何が問題か**: 押すべきボタンの名前が文言と違う。また、この帯は地図の上に約 100px の高さで出て地図を押し下げる
- **なぜ**: 基準 §3「文字のメニューだけに機能の意味を背負わせない」以前に、文言と部品が食い違うと迷う
- **直し方の案**: 文言を「もう一度読み込む」に合わせる（または文言を削り、ボタンだけにする）

### #12 縮小すると地区のまとまりの名前が分からない — 提案
- **どこ**: 縮小時（`.map-zoom-compact`）
- **何が問題か**: 縮小すると 3 つのまとまり（北・中・南）がはっきり分かれて見え、まとまりの理解には良い。ただ、どのまとまりが何地区かは書かれていない
- **なぜ**: REVIEW-BRIEF §1「どのようにまとまっているかが分かる」
- **直し方の案**: 縮小時だけ、各地区の区画の真ん中に地区名を薄く 1 つ出す（大きな札にはしない）。または縮小時にまとまりを押すとその地区へ移る

## §5 レビューの問いへの答え
| 問い | 答え | 根拠（実画面） |
|---|---|---|
| 説明文を読まずに、畑の位置とまとまりが分かるか | **分かる** | 開いた瞬間、航空写真の上に道の向きにそろった 4 本の帯が中央に並ぶ。縮小すると 3 つのまとまりが離れて見える。地区名は縮小時に無い（#12） |
| どこがタップできる圃場なのか、自然に分かるか | **おおむね分かる** | 白い輪郭で囲まれた帯だけが他の田畑と違って見える。ただ下の帯の 2/3 が灰色で「押せない物」が目に入る（#4） |
| 選んだ畑と表示された写真の対応を見失わないか | **同じ地区の中なら見失わない。地区をまたぐと見失う** | 選んだ畑の名前が大きくなり、板に番号と名前が出る。他の地区の畑を押すと地図が飛び、閉じると飛び戻る（#1）。選んだ線が収穫可能の塗りと同じ色（#2） |
| 名前・番号・状態が識別の助けになり、地図を覆っていないか | **覆っていない** | 札は箱が無く影つきの白い文字だけで、航空写真が透けて見える。縮小時は番号と「目安」だけ残る。ただ日付の意味が曖昧（#8）、未確定の点が説明されていない（#6） |
| 目安の畑と収穫可能な畑を見分けられるか。未確認を不可と誤解させないか | **見分けられる（選んでいないとき）**。未確認は地図では誤解しにくい | 目安は金の輪郭＋「目安」の文字、収穫可能は黄緑の塗り、収穫済は暗い塗り＋破線。選ぶと目安の金が消える（#2）。板の「□ 未確認」はチェックボックスに見える（#7） |
| 最初に目立つのが巨大な数字や装飾的な文字になっていないか | **なっていない**。ただし文字の中で一番強いのは上下の帯 | 大きな数字は無い。写真の枚数も「3 枚」と小さい。最大の文字は地区の選択欄・「写真を送る」・下の帯（17〜18px 太字）で、畑の名前（14px）より強い（#5） |
| 文字を消すだけ、アイコンに置き換えるだけで改善したつもりになっていないか | **一部ある** | アイコンは文字を消さずに添える形で、良い。一方、札の「可」を印に置き換えて日付だけ残した所は、日付の主語が消えた（#8）。板の未確認の印は新しい誤解を生んだ（#7）。比較のアイコンが「この畑の写真を見る」にも付いている（`selection-dock.tsx` の目安の畑のとき） |
| スマートフォンの実画面で、文字・写真・タップ範囲が無理なく使えるか | **おおむね使える** | ボタン・拡大縮小・閉じるは 44px。区画は 1 地区に合わせた倍率で帯の幅が約 30〜80px あり押しやすい。縮小 2 段でも 60px 前後。凡例・出典・「架空のもの」は 11〜12px で小さいが補助なので許容。板の写真は 96px で小さい（#9） |

## 良い点
- 開いたときの主役が航空写真と畑の帯になっている。上下の帯は細く、地図が画面の約 85%
- 区画が道の向きにそろった帯で、周りの田畑と同じ文法に見える（同じ形の繰り返しに見えない）
- 状態を色だけで言わず、塗り・破線・金の輪郭・文字を組み合わせている。凡例・札・板で同じ印を使っている
- 札に箱が無く、航空写真を覆わない。縮小すると名前を隠し番号と「目安」を残す段階の付け方が良い
- 板の写真の日付に年がある（「2026年7月19日」）。昨年を今年に見せない（§4）
- 写真が無い畑は「写真なし」「まだ確定した写真はありません」と言い、空の枠で見栄えを作っていない
- アイコンは文字を消さずに添えていて、読み上げは文字に任せている
- 他の地区の畑を押すと地区の選択欄も追従する（ただし #1 の飛びとセット）

## 範囲外の気づき（デザインではないので参考）
- `docs/spec.md` §8・§10 は「地図タイルを出さず、沖合の架空の村」のままで、この枝の「空知・地理院の航空写真」と食い違っている。`REVIEW-BRIEF.md` は航空写真を前提にしているので、spec の書き直しが要りそう（決定 P15 の変更の記録があるかの確認も）
- 区画の札の読み上げが「A-03 北の3、可 7/21」で、「可」を「か」と読む。板と同じく「収穫可能」と言う方が分かりやすい
