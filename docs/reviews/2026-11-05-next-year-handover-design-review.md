- 見た画面: 内蔵ブラウザ、375×812。開発サーバーに、判断・写真の差し込み（`demo-mock.js` と同じ値）を入れた
  - 地図: `/?today=2026-07-20` で A-03・A-04・A-07・A-11・A-09・A-06 を選んだ。比べるために `?today=2026-09-01`（メモを出さない日）でも同じ順に選んだ

- 重さ: **止める**（このまま出せない）／**直す**（提出前に直したい）／**見送ってよい**（余裕があれば）

## 判定

**このまま進めてよいです。止める指摘はありません。** 次のことは基準に合っています。
- 昨年の記録を、今年の判断の予想や日数として言っていません。
- 範囲の外では出ません。
- 年を見出しに書いています。
- 昨年の印を今年の記録へのリンクにしていません。

ただし、地図の板が伸びて選んだ畑を隠すこと（#1）、板の 1 文目が途中で切れて今年の判断と同じ形の文で並ぶこと（#2）、見比べるの昨年の印が今年の押せる札と同じ見た目なこと（#3）は、提出前に直したいです。

## 指摘

### #1 地図の板が 60〜70px 伸び、選んだ畑が板の下に隠れる — 直す
- **どこ**: 地図の選んだ畑の板。`src/components/map/selection-dock.tsx` の `.dock-last-memo` と、`src/app/home-client.tsx` の選んだ畑を見える所へ動かす処理（`keepSelectedVisible`、下の余白 240px 固定）
- **何が問題か**: メモの行が付くと、板の高さが 176〜186px から 238〜247px に増えます。地図を動かすときの下の余白（240px）は変わらないので、地区をまたいで選ぶと、選んだ畑の下の端が板に隠れました。

  | 選んだ畑（前の畑から） | メモなし（9/1）: 板の上端／畑の下端 | メモあり（7/20）: 板の上端／畑の下端 |
  |---|---|---|
  | A-11（A-04 から） | 567／559（見える） | 505／530（**25px 隠れる**） |
  | A-07（A-11 から） | 557／543（見える） | 496／543（**47px 隠れる**） |

- **なぜ**: BRIEF §3「選択後もどの場所を見ているか分かる」、§5「選んだ畑と表示された写真の対応を見失わないか」。1 回目の精査の #1（板で選んだ畑が隠れる）が、メモの行で戻っています。
- **直し方の案**: 次のどちらかです（両方でもよい）。
  - 下の余白を、板の実際の高さ（`ResizeObserver` などで測る）から決める。
  - 板のメモの行を 1 行に減らす（#2 の案）。62px の増えが 24px ほどになり、余白の 240px に収まります。

### #2 板の 1 文目が 2 行で切れ、今年の判断と同じ形の文がすぐ下に並ぶ — 直す
- **どこ**: 地図の板の「昨年の引き継ぎ（2025年）…」の行（`.dock-last-memo`、2 行で切る `-webkit-line-clamp: 2`）
- **何が問題か**:
  - **途中で切れる**: 見出し「昨年の引き継ぎ（2025年）」が 1 行目の半分を使うので、A-03 と A-04 は 3 行目に入る分が切れます（測ると必要な高さ 69px に対して表示は 46px）。
    - A-03: 「…収穫可能…」で切れ、「と判断した」が見えません。
    - A-04: 文の後半の「東の端が遅れていたと記録がある」が丸ごと見えません。昨年のメモで一番役に立つ所です。
  - **今年と昨年が同じ形で並ぶ**: すぐ上に今年の「7/21に収穫可能と判断」（緑の印つき）があり、その下に「7/20 に…収穫可能…」が来ます。日付と「収穫可能」が同じ形で 2 回並ぶので、年は小さな見出しの「（2025年）」だけでしか分かりません。
  - **重なり**: A-03・A-07 の 1 文目「北地区の目安の畑で、」は、板の「目安の畑」の札と同じことを言っています。
  - **続きの場所が分からない**: 行は押せず、続きがどこにあるか書かれていません。下のボタンは「この畑の写真を見る」で、メモがあるとは読めません。
- **なぜ**:
  - BRIEF §4「昨年を今年として見せない」。
  - BRIEF §3「情報の重要さと視覚的な強さを一致させる」。板の役目は最新の写真と今年の判断です。
  - AGENTS.md「言葉を盛らない」。切れた文は、言っていないことを補って読ませます。
- **直し方の案（推奨）**: 板には文を出さず、1 行の入口にします。
  - 例: 「（暦の印）昨年の引き継ぎ（2025年）あり ›」
  - 押すと `/fields/A-03#last-season-memo` に飛び、見比べるの全文に着きます。
  - 文を残すなら、次の 2 点を直します。
    - 見出しを別の行にして、文を 2 行に収める。
    - 「目安の畑で、」のように板と重なる部分は、メモの側で書かない。

### #3 見比べるの昨年の印が、今年の押せる札と同じ緑の札に見える — 直す
- **どこ**: 見比べるの「昨年の引き継ぎ（2025年）」の段の印「判断 7/20」「写真 7/17」「判断 7/24」（`src/components/compare/last-season-memo.tsx`、`.badge-source-static`）
- **何が問題か**:
  - **押せそうに見える**: 色・形・高さ（30px）は、今年の「引き継ぎメモ」の押せる印（`.badge-source`、リンク）と同じで、違いは枠が破線なことだけです。指で押しても何も起きません。破線は「ここに置く」「まだ空」と読まれることもあります。
  - **年が無い**: 印の言葉「判断 7/20」には年が無く、今年の印と同じ書き方です。今年も 7/20 前後に判断があると、今年の判断の札と区別が付きません。この画面ではすぐ下の「判断の履歴」が今年のものです。
- **なぜ**: BRIEF §4「昨年を今年として見せない」。コードの注（`globals.css`）は「押せる形に見せない」と書いていますが、実画面では押せる札の形のままです。
- **直し方の案**: 札にせず、文の後ろに小さな灰色の文字で出所を書きます（例「（2025/7/20 の判断）」）。札の形を残すなら、次の 2 点を直します。
  - 枠と色を灰色にする（`根拠なし` と同じ系統）。
  - 言葉に年を入れる（「2025 判断 7/20」）。

### #4 「昨年の同じ頃」と「昨年の引き継ぎ」が同じ事実を 2 回言い、今年の履歴を下に押す — 直す
- **どこ**: 見比べるの下の段。並びは「昨年の同じ頃」（121px）→「昨年の引き継ぎ」（347px）→「判断の履歴」→「引き継ぎメモ」（`src/app/fields/[id]/field-client.tsx` の 213〜214 行）
- **何が問題か**:
  - **同じ事実が 2 回出る**: 「昨年の同じ頃」が「昨年 7/20 に収穫可能と判断、7/24 に収穫済」と言い、そのすぐ下のメモの 1 文目と 3 文目が同じことを繰り返します。
  - **今年の履歴が遠くなる**: 347px の段が間に入るので、今年の「判断の履歴」が 1 画面ほど下に下がります。
  - **引き継ぎが離れて 2 つある**: 「昨年の引き継ぎ（2025年）」と、年の無い「引き継ぎメモ」（今年の分）が、履歴をはさんで離れて並びます。
- **なぜ**:
  - BRIEF §3「情報の重要さと視覚的な強さを一致させる」。
  - BRIEF §1「見るより読む感覚」への違和感。メモが出る時期（判断の頃）は、今年の判断と履歴がいちばん要る時期です。
- **直し方の案**:
  - 「昨年の同じ頃」の段の中に、メモを続けて入れて 1 段にする。見出しは「昨年の同じ頃（2025年）」1 つにする。
  - 昨年の同じ頃の 2 行と重なる文（判断・収穫済の日だけを言う文）は、全文を出す前に畳む（「昨年の引き継ぎを読む」で開く）。
  - 今年のメモの見出しは「今年の引き継ぎメモ」にする。

### #5 今日の差し替えが画面に出ず、URL から外してもタブの中で続く — 見送ってよい
- **どこ**: `src/lib/today.ts`（`sessionStorage` に残す）。画面のどこにも出ない
- **何が問題か**: `?today=2026-07-20` で開いた後、`?today` の無い `/#A-03` を開き直してもメモが出ました（保存された値が `2026-07-20` のまま）。デモを見る人も審査の人も、いまが差し替えた日なのか分かりません。逆に、11 月に普通に開くと何も出ないので、この段があることに気づけません。
- **なぜ**: BRIEF §5「説明文を読まずに…分かるか」。いまの日付の前提が見えないと、メモが出ている理由・出ていない理由が読めません。
- **直し方の案**: 差し替え中は、上の帯か地図の「架空のもの」の注の横に、小さく「7/20 として表示中（デモ）×」と出し、× で解除します。提出の説明（README・デモの手順）には `?today=2026-07-20` 付きの URL を書きます。

### #6 架空の注記の言い方 — 見送ってよい
- **どこ**: 見比べるの昨年のメモの最後「架空の例（手で書いたもの。Claude が作ったメモではない）」
- **何が問題か**: 正直で、提出には合っています。ただ、委員が読む画面としては、「Claude が作ったメモではない」は使い方に関係のない情報です。今年のメモの「（Claude が記録から作成）」と並べると、昨年のメモが劣ったもののように読めることもあります。地図の板の行には、この注記が付きません（地図の上の「区画の形・番号・判断は架空のもの」が覆っているとも読めます）。
- **直し方の案**: 提出版はこのままでよいです。本番で API から読む形に変えるときは、作った日と作り方（今年と同じ「（Claude が記録から作成）」）に揃えます。

## よい点
- **日数の差・「あと n 日」を言っていない**: 昨年の判断の日の前後だけ出す、という仕組みそのものが「今年の判断の予想」に見えやすいのに、画面の文は昨年の記録の言葉だけで、期限や予想の言葉が無いです（AGENTS.md「水分・収穫の可否を Claude に言わせない」）。
- **範囲の外では出ない**: A-09（昨年の記録はあるがメモが無い）・A-06（昨年は大豆）では行が出ず、板が伸びませんでした。9/1 ではどの畑にも出ませんでした。
- **年を見出しに書いている**: 「昨年の引き継ぎ（2025年）」と、昨年の分だと最初に言っています（#2・#3 は、その後の文と印に年が無い点です）。
- **リンクにしない判断**: 昨年の印を今年の履歴のアンカーに飛ばさない判断は正しいです（#3 は見た目がその判断に追い付いていない点です）。
- **地図を主役のまま**: 板の行は小さい灰色の文字で、地図や今年の判断より目立っていません。

## 確かめられなかったこと
- 開発サーバーには Worker の API が無いので、判断・写真は差し込みの値で見ました。見比べるでは差し込みが入らず、写真・履歴は「読み込めませんでした」のままです（依頼のとおり）。
- 今年の判断が昨年と同じ日（例: 今年も 7/20 に判断）になったときの見え方は、差し込みに無いので見ていません（#3 の懸念は、コードと言葉から書いています）。
- 終わりに `sessionStorage` の差し替えの値を消し、画面の大きさを戻しました。
