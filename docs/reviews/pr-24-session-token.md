### 指摘 1 の中身
`exp` をミリ秒で渡して管理者の Cookie を発行すると、30日と1秒後でも検証を通った。`Date.now()` は普通ミリ秒なので、起こりやすい間違い。

反対向きの間違いは安全側に倒れる。小数の `exp` と、ミリ秒の `nowSec` は、どちらも `null` になった。

## 「本人に確認したいこと」への意見（決めるのは人）
1. **期限の上限**: 決めることを勧める（指摘 1）
2. **端末 ID の長さ・文字種**: 検証に上限は要らない。`device` を読むのは署名が通った後なので、攻撃者は長い端末 ID を作れない。発行側で `crypto.randomUUID()` に固定すれば足りる
3. **別のセッションのレビューに回す判断**: 妥当。認証の部品で、§3 の「秘密に関わる PR」に当たると考える

## 受け口を作るときへの申し送り
- §6 では `SESSION_SECRET` を IP のハッシュの塩にも使う。この部品は Cookie の前半をそのまま署名するので、同じ鍵で HMAC を取るなら用途の印を付けて分ける。IP のハッシュは外に出ないので実害は小さい
- Cookie を無効にする手段は `SESSION_SECRET` の交換だけ。管理者の合言葉を変えても、発行済みの Cookie は最大30日残る
- `verifySessionToken` は、注入した `hmac` の例外を `null` にせずそのまま投げる。受け口で 500 にするか決める
