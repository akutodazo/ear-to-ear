## 指摘

### 1. 直す — #250: 「入り直す」の待ち時間に「出ています…」が出る（逆も）
`useRole` の `busy` が入り直すと出るの両方で 1 つなので、アカウントのシートの 2 つの部品が、押していない側の「処理中」も表示する。

- 再現 A: 委員として入った端末で札を押す →「合言葉を入れ直す」→ 合言葉を入れて「入り直す」。応答を待つ間、その下の「この端末から出る」が**「出ています…」**に変わる（押していないのに、出ているように見える）
- 再現 B: 同じシートで「合言葉を入れ直す」の欄を開いたまま「この端末から出る」を押す。待つ間、欄の送るボタンが**「確かめています…」**になる。出られなかったときの文（「出られませんでした…」）は、欄が開いていると合言葉の欄の中（`PassphraseForm` の `message`）に出るので、合言葉が違ったように読める
- 害: 操作は壊れない（どちらも押せなくなるだけ）。ただ、委員長が入り直す途中で「出ています…」を見て、出てしまったと思い込む
- 直し方の案: Presenter の状態を `pending: "sign-in" | "sign-out" | null` にし、ボタンの言葉はそれぞれの種類のときだけ変える（押せなくするのは両方でよい）。文も入り直しと出るで分ける

### 2. 直す（軽い）— #250 を先にマージできてしまう
#250 の本文は「#249 を先にマージする」と書くが、両方とも main を土台にした別々の PR で、どちらも `mergeable: clean`。#249 は worker/ なので先輩の確認を待つ。#250 は Claude の PR の決まり（CI が通れば自動マージ）に乗せると先に入りうる。

- 再現: #250 だけが main に入り Actions が dev にデプロイした後、入っている端末で札 →「この端末から出る」→ Worker が 405（`Allow: POST, GET`）→ 「出られませんでした。もう一度押してください」が出て、何度押しても出られない
- 直し方の案（どれか 1 つ）: #250 の土台を `feat/logout-api` にする（#249 が入ると GitHub が自動で main に付け替える）／#250 に「#249 のマージ待ち」と書いて自動マージを付けないことを PR に明記する／#250 の本文の先頭に順を太字で書く（今は本文の中ほど）

### 3. 見送ってよい — 「出る」は写された Cookie を無効にしない
トークンは署名だけで持つので、消えるのはこの端末の Cookie だけ。写された値は期限（30 日）まで使える。ボタンの言葉が「この端末から出る」で、言いすぎていない。#249 の弱点候補 1 に書いてあり、今までと同じ（取り消しの一覧は決定に無い）。

### 4. 見送ってよい — 委員長が委員の合言葉を入れると、黙って委員に下がる
- 再現: 委員長の端末で「合言葉を入れ直す」→ 委員の合言葉 →「入り直す」。確かめずに画面を読み直し、札が「委員」になる
- 欄の説明に「委員の合言葉なら、委員として入り直します」と書いてあり、委員長の合言葉を入れ直せば戻れる。#250 の弱点候補 2 にある

### 5. 見送ってよい — 役割を読めなかった端末には「出る」が出ない
`getRole` がつながらない・500 のとき、役割は `null`（入っていない）として扱われ、シートは「入っていません」で「出る」を出さない。Cookie は残ったまま。
- 再現: 入っている端末で電波の悪い所で画面を開く → 札が「入る」→ シートに「出る」が無い
- 前からの振る舞い（#194）で、電波が戻って読み直せば出る

### 6. 見送ってよい — 入り直しの失敗で、同じ IP の枠を使う
入り直しで合言葉を間違えると、`POST /api/session` の「IP ごとに 10 分に 5 回」の枠を 1 つ使う（入ったままにはなる。失敗の応答は Set-Cookie を返さないので、今の Cookie は消えない）。同じ回線（家の Wi-Fi・携帯のまとめた IPv4）の委員とは枠を分け合う。入り直す場所が増えた分、間違いは増えうるが、決定（11-03）の範囲。

### 7. 見送ってよい — #249 のテストが名前ほどは確かめていない
`session-logout.test.ts` の「壊れた Cookie でも 204（照合しない）」は `hmac.verify` が呼ばれないことを見ていない。「D1 にも R2 にも触れない」は `db.prepare` だけ見て、`photos` の `get`・`put`・`delete` は見ていない。実装（`deleteSession` は引数を使わない）は正しいので、今は害が無い。後で誰かが照合を足したときに気づけない程度。
