## 確かめたこと
リポジトリのファイルは作らず、変えていない。試しは一時フォルダで、`photo-meta.ts` を写したもの（型の import だけ置き換え）に対して行った。最後の `git status --porcelain --untracked-files=all` は空。

1. **凍結テストを写した実装に対して実行**: リポジトリの vitest で、一時フォルダの写しとテストを実行 → `Tests 23 passed (23)`。
2. **テストが誤りを捕まえるか（実装をわざと誤らせる）**: 1か所ずつ変えて 23 件を回した。
   - 捕まえた: 0,0 を通す（1件失敗）／緯度の範囲を見ない（1）／`GpsLongtitude` を読まない（1）／位置を EXIF 優先にする（1）／OffsetTimeOriginal を無視（2）／S の符号を無視（1）／W の符号を無視（1）
   - **捕まえない**: 時差なしを UTC とみなす（#1）／両方に日付があるとき EXIF を優先する（#2）／経度の範囲を見ない／`Date.UTC` の往復をやめる／SOS の後ろも読む／EXIF の部分的な安全網を外す／N/S の参照が無くても読む（#4）
3. **壊れた入力**（`node --experimental-transform-types edge.ts`）:
   - 正しい JPEG を 0〜282 バイトのすべての長さで切る → 例外 0
   - ランダムに 1〜6 バイト壊すことを 5 万回 → 例外 0、いちばん長くて 0.24ms
   - GPS IFD のオフセットが範囲外／項目数 0xFFFF／項目数 900（ファイルの終わりを越えて読む）／有理数の個数 0xFFFFFFFF／有理数のオフセット 0xFFFFFFFF → どれも位置 null、例外なし
   - COM セグメント 300 万個（12MB）→ 11ms。詰め物の FF 12MB → 31ms（止まらない）
   - 細工した XMP → APP1 1つで 80〜134ms、180 個（約 12MB）で 13,625ms（#3）。正規表現を `[^<>]*` に変えると 160ms
4. **日付と位置の端**: `2026-02-29` → null、`2028-02-29` → そのまま、`+0900` を受ける、`24:00:00` → null、`2026-07`（日が無い）→ null、時差 `+15:00` → null、`9999-12-31T23:00:00-05:00`（日本時間で 1 万年になる）→ null、経度 180 → 受ける、180.0001 → null、`-0,-0` → null、`1e1` → null、`GpsLatitudeRef` を緯度と読み違えない、接頭辞が `drone:` のときは読まない、SOS の後ろの XMP は読まない。
5. **呼び出し元**: `git grep` で `photo-meta`／`readPhotoMeta` を使う所は無い（`src/lib/upload-steps.ts` のコメントで「T01 で置き換える」と触れているだけ）。
