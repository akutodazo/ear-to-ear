## 2. 本人の手順（dev、合成写真だけ）

### A. iPhone で 4 段と、番号の付け替え（条件 1・3・4・5）
1. iPhone の Safari で合言葉 → 合成写真を 1 枚選ぶ → 送る
2. もう一方の端末（PC か Android）で新着を「更新」→ その写真が「未確定（推定 ○○）」で出る
3. 管理者の端末で、その写真を候補の番号に確定する
4. iPhone で新着を「更新」→ 「確定 ○○」になっている
5. 管理者の端末で、同じ写真を**別の番号に変える**（例 A-06 → A-07）
6. もう一方の端末で「更新」→ 新しい番号で出る。**写真の枚数が増えていない**（同じ写真が 2 行にならない）
7. 圃場ページ `/fields/A-07` を開くと、その写真が出て、`/fields/A-06` からは消えている（L1 の部品だが、付け替えの確かめに使える）

### B. 401 と 403（条件 6。PC のブラウザで）
1. **合言葉なし**: プライベートウィンドウで dev を開き、写真を送ろうとする → 合言葉の入力が出る（送れない）。開発者ツールのネットワークで `POST /api/uploads` が 401 なら、なお良い
2. **委員の合言葉**: プライベートウィンドウで、**委員の**合言葉で入る（`/upload` で合言葉を入れる）
3. 新着に「確定・変更」が出ないことを見る（画面は管理者にだけ出す）
4. 開発者ツールのコンソールで、新着の写真の id を 1 つ使って次を打つ → `403` が出る

   ```js
   fetch("/api/photos/<写真の id>/assignment", { method: "PATCH", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ fieldId: "A-01" }) }).then((r) => r.status)
   ```

   写真の id は、同じウィンドウで `/api/photos/recent` を開くと最初の `"id"` に出ている。**合言葉の値はどこにも貼らない**

### C. 撮影位置が残っていない（条件 2。`--remote` を使うので本人のリポジトリのフォルダで）
1. D1 の列に座標が無い:

   ```bash
   npx wrangler d1 execute DB --remote --env dev --command "PRAGMA table_info(uploaded_photos)"
   ```

   列の名前に緯度・経度・距離に当たるもの（lat・lng・gps・distance など）が無いことを見る
2. 配信される画像に APP1〜15 が無い（新着の写真の id を 1 つ使う。dev の URL は本人の手元のもの）:

   ```bash
   curl -s https://<dev の URL>/api/photo-files/<写真の id> -o l0-check.jpg
   ```

   ```bash
   node --input-type=module -e "import {readFileSync} from 'node:fs'; import {inspectJpeg} from './src/services/jpeg-segments.ts'; console.log(inspectJpeg(new Uint8Array(readFileSync('l0-check.jpg'))).appSegments)"
   ```

   `[]`（または APP0 の `224` だけ）なら合格（`MODULE_TYPELESS_PACKAGE_JSON` の警告は出てよい。11-04 に合成写真でこのコマンドが動くことを確かめた）。確かめた後に `l0-check.jpg` を消す
