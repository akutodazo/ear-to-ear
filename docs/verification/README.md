# 検証記録（実機・二端末・試用）

合格条件（`docs/spec.md` §9）のうち、自動のテストだけでは確かめられないものの記録を置く（Issue #11）。§9 の表の「状態」から、ここのファイルへたどれるようにする。

## 1つのファイルに書くこと
ファイル名は `YYYY-MM-DD-<何を>.md`（例 `2026-11-03-dev-mobile.md`）。

| 項目 | 中身 |
|---|---|
| 日付・誰が | 日本時間。実際に操作した人 |
| 環境 | dev／demo／手元、main のコミット、端末とブラウザ（分かれば OS の版） |
| 使ったデータ | 合成写真（`node scripts/make-fixtures.mjs`）など。**架空のものだけ** |
| 手順 | 何を押したか |
| 結果 | 期待と実際。分からなかったこと・記録していないことも書く |
| 直したこと | 見つかった問題と、その PR・Issue |
| 対応する合格条件 | §9 の番号 |

## 書かないこと
- 実在の圃場・人・写真・座標（K10）。実写真で測る合格条件 7 は、割合と枚数だけを書き、写真と正解表は手元に置く
- 合言葉・`SESSION_SECRET`・API キーの値、dev の URL の中のアカウント名
